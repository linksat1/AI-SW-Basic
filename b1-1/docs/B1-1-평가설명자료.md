### 2-1. 프로세스/포트 확인 명령 선택 이유

**프로세스 확인: `pgrep -f`를 쓴 이유**
```bash
PID=$(pgrep -f "agent-app-linux-arm64" | head -1)
```

| 명령어 | 특징 |
|--------|------|
| `pgrep -f` | 프로세스 전체 이름(경로 포함)으로 검색, 숫자(PID)만 반환 |
| `ps aux | grep` | 자기 자신 grep 프로세스도 함께 잡히는 문제 발생 |

→ `pgrep -f`가 더 정확하고 깔끔하게 PID만 추출됩니다.

**포트 확인: `ss -tulnp`를 쓴 이유**
```bash
PORT_STATUS=$(ss -tulnp | grep ":15034 ")
```

| 명령어 | 특징 |
|--------|------|
| `ss -tulnp` | 현대 리눅스 표준, 빠르고 정확 |
| `netstat` | 오래된 명령어, 최신 Ubuntu에서 기본 미설치 |

→ Ubuntu 22.04 기본 도구이므로 `ss`를 선택했습니다.

### 2-2. CPU/MEM/DISK 추출 방법

**CPU — `top` + `awk`:**
```bash
CPU_USAGE=$(top -bn1 | grep "Cpu(s)" | awk '{print $2}' | cut -d'%' -f1)
```
- `top -bn1`: 1회 실행(batch 모드)
- `awk '{print $2}'`: 두 번째 컬럼(사용률)만 추출

**메모리 — `free` 명령:**
```bash
MEM_TOTAL=$(free | grep Mem | awk '{print $2}')
MEM_USED=$(free  | grep Mem | awk '{print $3}')
MEM_USAGE=$(awk "BEGIN {printf \"%.1f\", ($MEM_USED / $MEM_TOTAL) * 100}")
```
- total/used 값을 직접 계산 → 소수점 1자리까지 정확하게 표시

**디스크 — `df`:**
```bash
DISK_USAGE=$(df / | tail -1 | awk '{print $5}' | tr -d '%')
```
- 루트(`/`) 파티션 기준
- `%` 기호 제거 후 숫자만 저장

**로그 포맷을 고정한 이유:**
```
[2026-05-26 20:51:01] PID:1570 CPU:2.3% MEM:4.2% DISK_USED:1%
```
- `awk`로 파싱하기 쉬운 `키:값` 형태로 통일
- `report.sh`가 이 포맷을 기준으로 자동 분석하기 때문

📂 **실행 결과 증거:** `evidence/step8_monitor_sh.md` → rotate_log() 함수 구현 코드 항목 / `scripts/monitor.sh` 22~35번째 줄

**`logrotate` 대신 스크립트로 직접 구현한 이유:**  
→ 외부 도구 의존 없이 monitor.sh 안에서 자체 완결  
→ 10MB / 10개 조건을 코드로 명확히 표현 가능

**rotate_log() 함수 동작 순서:**
```
1. 현재 로그 파일 크기 확인 (stat -c%s)
2. 10MB(10,485,760 bytes) 이상이면 회전 시작
3. .9 → 삭제, .8 → .9, ... .1 → .2 (뒤에서부터 번호 올리기)
4. monitor.log → monitor.log.1 로 이동
5. 새 빈 monitor.log 생성 (touch)
```

## 📋 항목 3 — 보안 설계 이유 설명 (왜 이렇게 설계했는지)

---

### 3-1. SSH 포트 변경 + Root 차단의 보안 효과

**위협 모델:**  
> 인터넷에 연결된 서버는 매일 수천 번의 자동화된 무차별 대입 공격(Brute Force)을 받습니다.

| 공격 방식 | 기본 포트 22 | 포트 20022 |
|-----------|-------------|-----------|
| 자동 스캔봇 | 즉시 발견 | 대부분 무시 |
| root 로그인 시도 | 성공 가능 | 차단됨 |

- **포트 변경**: 공격 대상에서 자동으로 제외됨 (노이즈 감소)
- **Root 차단**: 뚫려도 root 권한 탈취 불가, 일반 계정으로만 접근

---

### 3-2. api_keys와 로그 디렉토리를 agent-core로 제한한 이유

**최소 권한 원칙 (Principle of Least Privilege):**  
> "필요한 사람에게만, 필요한 만큼만 권한을 준다."

```
api_keys/           agent-core만 접근 (admin + dev)
/var/log/agent-app/ agent-core만 접근 (admin + dev)
```

- `agent-test`는 테스트 계정 → API 키나 운영 로그 접근 불필요
- 실수나 악의적 접근으로 인한 피해 범위를 최소화

---

### 3-3. 경고만 하고 종료하지 않는 항목을 분리한 이유

**종료(exit 1)하는 항목:**
- 프로세스 다운 → 서비스 중단 상태 → 즉시 알려야 함
- 포트 닫힘 → 서비스 불가 상태 → 즉시 알려야 함

**경고만 하는 항목:**
- 방화벽 비활성화: 보안 위험이지만 서비스 자체는 살아있음
- CPU/MEM/DISK 임계치 초과: 일시적 급증일 수 있음, 서비스는 정상

**운영상의 이유:**  
> exit 1로 종료하면 cron이 "실패"로 기록하고 이후 로그도 안 쌓임.  
> 경고만 하면 계속 모니터링하면서 상태 기록이 누적됨 → 트렌드 분석 가능

---

### 3-4. `>` vs `>>` 차이와 로그에 `>>`를 쓴 이유

| 기호 | 동작 | 결과 |
|------|------|------|
| `>` | 덮어쓰기 | 기존 내용 삭제 후 새로 작성 |
| `>>` | 이어쓰기 | 기존 내용 유지하고 뒤에 추가 |

```bash
# 잘못된 방법 (매분 로그가 1줄로 덮어씌워짐)
echo "[타임스탬프] ..." > monitor.log

# 올바른 방법 (매분 1줄씩 누적)
echo "[타임스탬프] ..." >> monitor.log
```

monitor.sh 코드에도 주석으로 명시되어 있습니다:
```bash
# 로그 한 줄 추가 기록 (>> : 누적 기록, > 는 덮어쓰므로 절대 사용 금지)
echo "[${TIMESTAMP}] PID:..." >> "$LOG_FILE"
```

|-----------|---------|--------------|
| 프로세스명 | agent-app-linux-arm64 | nginx |

| 로그 경로 | /var/log/agent-app/ | /var/log/nginx/ |

---

### 4-2. 프로세스는 살아있는데 포트가 안 열리는 상황

**이 상황의 의미:**  
> 프로세스는 떠 있지만 네트워크에 연결이 안 됨 → 서비스 불가

**원인 후보 & 확인 순서:**

```
1단계: 포트 바인딩 실패인지 확인
  → ss -tlnp | grep 15034
  → 아무것도 안 나오면 앱이 포트를 못 열었음

2단계: 앱 로그 확인
  → tail -50 /var/log/agent-app/monitor.log
  → 에러 메시지 확인 (권한 부족? 포트 충돌?)

3단계: 포트 충돌 확인
  → ss -tlnp | grep 15034
  → 다른 프로세스가 이미 15034를 쓰고 있는지 확인

4단계: 방화벽 확인
  → sudo ufw status
  → 포트가 허용되어 있는지 확인

5단계: 앱 재시작
  → 프로세스 kill 후 재시작
```

---

### 4-3. 로그가 급증해 디스크가 가득 찰 위험

**단기 대응 (지금 당장):**
```bash
# 1. 디스크 상황 파악
df -h

# 2. 큰 파일 찾기
du -sh /var/log/agent-app/*

# 3. 오래된 로그 즉시 압축
gzip /var/log/agent-app/monitor.log.5
gzip /var/log/agent-app/monitor.log.6

# 4. 필요 시 오래된 것 삭제
rm /var/log/agent-app/monitor.log.9
```

**중기 대응 (재발 방지):**
- `MAX_LOG_SIZE`를 더 작게 줄임 (예: 5MB)
- `MAX_LOG_FILES`를 더 줄임 (예: 5개)
- `log_archive.sh` 실행 주기를 더 자주 (매일 실행)
- 디스크 80% 경고 임계값 낮추기 (80% → 70%)

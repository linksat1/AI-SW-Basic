## 1. 과제 개요

**만들어야 하는 것**: 표준 라이브러리만 사용한 Python CLI 가계부 프로그램

**완성 기준** (`budget_app/` 폴더에 이미 구현되어 있음):
- [x] add / list / search / summary / budget / category / update / delete / import / export 10개 명령
- [x] 데이터 3개 파일(transactions/categories/budgets)로 영구 저장 (JSONL)
- [x] 제너레이터 기반 스트리밍 조회
- [x] 데코레이터로 예외 처리 + 실행 로그/시간 측정 분리
- [x] dataclass 모델 + 타입 힌트
- [x] `README.md`(실행 방법, 저장 형식, 명령 예시, CSV 스키마)

**폴더 구조**:
```
b2-1/
├── 가이드.md          ← 지금 보고 있는 이 문서
├── 과제                ← 원본 과제 요구사항 (참고용, 수정 X)
└── budget_app/         ← 실제 구현체 (제출물)
    ├── __main__.py
    ├── cli.py
    ├── service.py
    ├── repository.py
    ├── models.py
    ├── decorators.py
    ├── errors.py
    └── README.md        ← 과제가 요구하는 실행/저장/명령/CSV 스키마 설명
```

## 2. 개발 환경 준비

이 과제는 **Python 3.10 이상**이 필요합니다.

```bash
python3 --version
```

만약 3.9 이하로 나온다면, 이 PC에는 이미 Python 3.12가 별도로 설치되어 있으니 그걸 사용하면 됩니다.

```bash
/usr/local/bin/python3.12 --version
```

앞으로 이 가이드의 모든 `python3` 명령은, 3.10 미만이 기본으로 잡혀 있다면
`/usr/local/bin/python3.12`로 바꿔서 실행하세요. (또는 `alias python3=/usr/local/bin/python3.12`로
터미널 세션에서 별칭을 만들어두면 편합니다.)

외부 라이브러리 설치(`pip install`)는 전혀 필요 없습니다. 표준 라이브러리만 사용했습니다.

## 3. 실행해보기

**항상 `b2-1` 폴더에서 실행해야 합니다.** (`budget_app`이 그 안의 하위 폴더이기 때문입니다.)

```bash
cd b2-1
```

### 3-1. 도움말 먼저 확인

```bash
python3 -m budget_app --help
```

전체 명령 목록이 나옵니다. 각 명령의 자세한 옵션은 아래처럼 확인합니다.

```bash
python3 -m budget_app add --help
python3 -m budget_app search --help
```

### 3-2. 거래 추가 (`add`, 대화형)

```bash
python3 -m budget_app add
```

아래처럼 순서대로 입력해봅니다.

```
날짜(YYYY-MM-DD): 2024-01-15
타입(income/expense): expense
카테고리: food
금액(양수): 15000
메모(선택): 점심
태그(쉼표로 구분, 없으면 엔터): meal
```

`[저장 완료] id=TX-000001`이 출력되면 성공입니다. 같은 방식으로 2~3건 더 추가해보세요
(수입 1건 포함하면 이후 실습이 더 자연스럽습니다).

> **잘못 입력하면?** 날짜 형식이 틀리거나 금액이 음수면 `[오류]`와 `[힌트]`를 보여주고
> 같은 항목을 다시 물어봅니다. 프로그램이 죽지 않고 재입력을 받는지 확인해보세요.

### 3-3. 목록 조회 (`list`)

```bash
python3 -m budget_app list
python3 -m budget_app list --limit 2
```

가장 최근에 추가한 거래부터 위에서부터 나옵니다.

### 3-4. 검색 (`search`)

```bash
python3 -m budget_app search --category food
python3 -m budget_app search --from 2024-01-01 --to 2024-01-31
python3 -m budget_app search --q 점심
```

### 3-5. 월별 요약 (`summary`)

```bash
python3 -m budget_app summary --month 2024-01 --top 3
```

총 수입/총 지출/잔액과, 지출이 큰 카테고리 순위가 나옵니다.
데이터가 없는 달을 조회하면 `[안내] 2024-99 데이터 없음`처럼 명확히 표시됩니다.

### 3-6. 예산 설정 후 다시 요약 (`budget`)

```bash
python3 -m budget_app budget set --month 2024-01 --amount 100000
python3 -m budget_app summary --month 2024-01 --top 3
```

지출이 예산을 넘으면 `[경고] 이번 달 예산을 초과했습니다.`가 함께 출력되는지 확인하세요.

### 3-7. 카테고리 관리 (`category`)

```bash
python3 -m budget_app category list
python3 -m budget_app category add
# 카테고리명: book

python3 -m budget_app category remove
# 삭제할 카테고리명: food   <- 이미 거래에서 쓰이고 있으면 삭제가 막힘을 확인
```

### 3-8. 수정/삭제 (`update` / `delete`)

```bash
python3 -m budget_app update --id TX-000001 --amount 18000 --memo "점심(수정)"
python3 -m budget_app delete --id TX-000001
```

존재하지 않는 id로 시도하면 오류 메시지가 나오고, 종료 코드가 0이 아닌지 확인해보세요.

```bash
python3 -m budget_app delete --id TX-999999
echo "종료 코드: $?"
```

### 3-9. 내보내기 / 가져오기 (`export` / `import`)

```bash
python3 -m budget_app export --out export.csv --month 2024-01
cat export.csv
```

```bash
cat > import.csv <<'EOF'
date,type,category,amount,memo,tags
2024-02-01,expense,food,5000,아침,
2024-02-05,income,salary,100000,보너스,
EOF

python3 -m budget_app import --from import.csv
```

`imported=N, skipped=M` 형태로 처리 결과가 나옵니다.

### 3-10. 저장 파일과 로그 확인

```bash
ls data/
cat data/transactions.jsonl
cat budget_app.log
```

`data/` 안에 `transactions.jsonl`, `categories.jsonl`, `budgets.jsonl` 3개 파일이 보이고,
`budget_app.log`에 방금 실행한 명령들의 실행 기록(시간)이 쌓여 있으면 정상입니다.

## 4. 코드 구조 한눈에 보기

| 파일 | 역할 | 한 줄 설명 |
|---|---|---|
| `__main__.py` | 진입점 | `python -m budget_app`으로 실행하면 가장 먼저 호출됨 |
| `cli.py` | 입출력 담당 | 사용자 입력을 받고 화면에 결과를 보여줌 (검증/저장은 안 함) |
| `service.py` | 규칙/검증 담당 | 날짜/금액 형식 검사, 예산 계산, CSV 변환 등 "판단"을 담당 |
| `repository.py` | 파일 저장 담당 | JSONL 파일을 어떻게 읽고 쓰는지만 담당 |
| `models.py` | 데이터 구조 | `Transaction` dataclass (거래 1건의 모양) |
| `decorators.py` | 공통 기능 | 예외 처리, 실행 로그+시간 측정을 다른 코드와 분리 |
| `errors.py` | 오류 타입 | 사용자에게 보여줄 "예상된 오류"를 표현하는 `AppError` |

**왜 이렇게 나눴나요?**: `cli.py`만 봐도 "이 프로그램이 어떤 명령을 받는지" 알 수 있고,
`service.py`만 봐도 "이 프로그램의 규칙이 뭔지" 알 수 있습니다. 만약 한 파일에 다 몰아넣으면
카테고리 검증 로직을 고치려다가 화면 출력 코드까지 건드리게 되는 식으로 실수가 늘어납니다.

## 5. 핵심 개념 쉽게 이해하기

### 제너레이터(yield)로 스트리밍 처리하는 이유

`repository.py`의 `iter_all()`은 파일 전체를 리스트로 만들어 반환하지 않고,
`yield`로 한 줄씩 돌려줍니다.

```python
def iter_all(self) -> Iterator[Transaction]:
    for row in _read_jsonl(self.path):
        yield Transaction.from_dict(row)
```

**비유**: 책 한 권을 통째로 복사해서 들고 다니는 대신, 필요한 페이지를 그때그때 한 장씩
넘겨보는 것과 같습니다. 거래가 100만 건이어도 한 번에 메모리에 다 올리지 않고
한 줄씩 처리할 수 있습니다.

`list` 명령의 `latest()`는 여기서 한 걸음 더 나아가, "최근 N개"만 필요하므로
`deque(maxlen=N)`이라는 크기 제한된 상자를 만들어 한 줄씩 넣으면서 오래된 것은 자동으로
버립니다. 그래서 파일 크기와 상관없이 항상 딱 N개만큼의 메모리만 사용합니다.

### 데코레이터로 공통 관심사를 분리하는 이유

```python
@handle_errors
@log_execution
def cmd_add(args):
    ...
```

**비유**: 모든 명령마다 "실행 시간 재고, 로그 남기고, 에러 나면 예쁘게 출력하고"를
직접 써넣으면 코드가 지저분해집니다. 데코레이터는 이런 "부가 기능"을 함수 바깥에서
감싸서, `cmd_add` 본문은 "무엇을 할지"에만 집중하게 해줍니다.

- `log_execution`: 함수 실행 전후 시간을 재서 `budget_app.log`에 기록
- `handle_errors`: 함수 안에서 발생한 `AppError`(또는 예상 못한 오류)를 잡아서
  스택트레이스 대신 `[오류]`/`[힌트]` 메시지로 바꾸고, 종료 코드를 정해줌

### 타입 힌트를 쓰면 좋은 점

```python
def validate_amount(amount_str: str) -> int:
    ...

@dataclass
class Transaction:
    id: str
    amount: int
    tags: list[str] = field(default_factory=list)
```

**비유**: 타입 힌트는 함수에 붙이는 "설명서"입니다. `validate_amount`가 문자열을 받아서
정수를 돌려준다는 걸 코드만 보고 바로 알 수 있고, 에디터가 실수(예: 문자열에 정수 메서드를
쓰려는 경우)를 미리 잡아줍니다. 실행 중에 강제로 타입을 검사하지는 않지만,
"이 함수와 어떻게 대화해야 하는지"에 대한 계약을 명확히 해줍니다.

### dataclass를 쓰는 이유

```python
@dataclass
class Transaction:
    id: str
    date: str
    type: str
    category: str
    amount: int
    memo: str = ""
    tags: list[str] = field(default_factory=list)
```

일반 클래스처럼 `__init__`을 직접 쓸 필요 없이 필드만 나열하면 되고,
`asdict()`로 딕셔너리 변환도 자동으로 지원됩니다. "이 데이터가 어떤 필드로 구성되는지"가
클래스 정의 한 곳에 명확히 드러납니다.

## 7. 자주 발생하는 문제 해결

### `ModuleNotFoundError: No module named 'budget_app'`
- `b2-1` 폴더 **안에서** 실행하고 있는지 확인하세요. `cd b2-1` 후 다시 실행합니다.

### `SyntaxError` 또는 `list[str]` 관련 오류
- Python 버전이 3.10 미만일 수 있습니다. `python3 --version`으로 확인 후,
  이 PC에 이미 설치된 `/usr/local/bin/python3.12`를 사용하세요.

### `category`가 없다고 나옴 (등록되지 않은 카테고리)
- `python3 -m budget_app category list`로 등록된 카테고리를 먼저 확인하세요.
- 처음 실행 시 `food, transport, rent, salary, etc`가 자동으로 생성되어 있어야 합니다.
  안 보인다면 `data/categories.jsonl` 파일이 정상 생성됐는지 확인하세요.

### `update`/`delete`가 안 먹힘
- `--id` 값이 정확한지 `list` 또는 `search` 결과에서 다시 확인하세요.
- id는 `TX-000001`처럼 앞자리 0을 포함한 6자리 숫자 형식입니다.

### CSV import 시 `skipped` 숫자가 예상보다 많음
- CSV의 `date`가 `YYYY-MM-DD` 형식인지, `type`이 정확히 `income`/`expense`인지,
  `category`가 이미 등록된 이름인지 확인하세요. 조건에 안 맞는 행은 조용히 건너뛰고
  마지막에 `skipped` 개수로만 알려줍니다.

### `budget_app.log` 파일이 계속 쌓여서 지저분함
- 학습/테스트 중이라면 `rm budget_app.log`로 지우고 다시 실행해도 됩니다
  (제출 전 최종 실행 기록만 남기고 싶다면 이 방법을 사용하세요).

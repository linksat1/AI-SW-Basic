# B2-1 가계부 콘솔 프로그램 — 실행 결과 제출자료

`가이드.md`의 3장(실행해보기)을 처음부터 끝까지 실제로 실행한 결과입니다.
실행 환경: `/usr/local/bin/python3.12` (Python 3.12.13), 실행 위치: `b2-1/` (기본 `--data-dir` = `./data`)

모든 원본 캡처는 [`results/`](results/) 폴더에 명령별 텍스트 파일로 들어 있습니다.
아래는 그 결과를 과제의 "2. 최종 결과물" 10개 기능 순서에 맞춰 정리한 요약입니다.

---

## 5. 예산 (budget)

`budget set --month 2024-01 --amount 100000` 실행 후 ([results/06_budget_set.txt](results/06_budget_set.txt)):

이후 `summary`를 다시 실행하면 사용률과 초과 경고가 함께 출력됩니다
([results/07_summary_after_budget.txt](results/07_summary_after_budget.txt)):

```

```

## 6. 카테고리 관리 (category)

- `category add` → `book` 추가 성공 ([results/09_category_add.txt](results/09_category_add.txt))
- `category remove` → `food`는 사용 중이라 **삭제 차단** ([results/09_category_remove_blocked.txt](results/09_category_remove_blocked.txt)):
  `[오류] 'food' 카테고리를 사용 중인 거래가 있어 삭제할 수 없습니다.` (종료 코드 1)
- `category remove` → `book`(미사용)은 정상 삭제 ([results/09_category_remove_ok.txt](results/09_category_remove_ok.txt))

## 7. 수정 / 삭제 (update / delete)

- `update --id TX-000001 --amount 18000 --memo 점심(수정)` → `[수정 완료] id=TX-000001` ([results/10_update.txt](results/10_update.txt))
- 존재하지 않는 id로 `update`/`delete` 시도 시 오류 메시지 + **종료 코드 1**로 정상 처리
  ([results/10_update_not_found.txt](results/10_update_not_found.txt), [results/10_delete_not_found.txt](results/10_delete_not_found.txt))
- `delete --id TX-000003` → 정상 삭제 ([results/10_delete_ok.txt](results/10_delete_ok.txt))

## 8. 가져오기 / 내보내기 (import / export)

- `export --out export.csv --month 2024-01` → `[완료] export.csv (3 records)` (이 시점엔 TX-000003이
  이미 삭제된 상태) ([results/11_export.txt](results/11_export.txt)).
  [export_예시.csv](export_예시.csv)는 전체 시나리오(9번 항목의 재입력 테스트로 추가된 거래 포함)를
  마친 뒤 다시 내보낸 파일이라 4건이 들어 있습니다 — 두 실행 시점의 데이터 상태 차이입니다.
- `export` 조건(--month 또는 --from/--to) 없이 실행하면 오류 처리 확인
  ([results/11_export_missing_condition.txt](results/11_export_missing_condition.txt))
- `import --from import_test.csv` (정상 2건 + 잘못된 날짜 1건 포함, 원본은 [import_예시.csv](import_예시.csv)) →
  `[완료] imported=2, skipped=1` ([results/12_import.txt](results/12_import.txt))

## 9. 입력 검증 / 재입력 흐름

`add` 실행 중 잘못된 날짜(`2024-13-40`)를 입력하면 오류 메시지를 보여주고 같은 항목을
다시 묻습니다. 프로그램이 중단되지 않고 정상 입력을 받아 저장까지 완료됩니다.
([results/13_add_invalid_date_retry.txt](results/13_add_invalid_date_retry.txt))

## 요구사항 대조 체크리스트

| 요구사항 | 확인 결과 |
|---|---|
| 10개 명령 정상 동작 | 위 0~9 항목에서 전부 실행 확인 |
| 데이터 3개 파일 영구 저장 | `transactions/categories/budgets.jsonl` 3개 생성 확인 |
| 제너레이터 스트리밍 조회 | `list`/`search`가 `repository.py`의 `yield` 기반 함수로 동작 (코드: `budget_app/repository.py`) |
| 데코레이터로 공통 관심사 분리 | `handle_errors`/`log_execution` 적용, 로그 파일에서 확인 |
| 입력 검증 + 재입력 | 잘못된 날짜 재입력 시나리오로 확인 |
| 존재하지 않는 id 처리 | update/delete 실패 시 오류 메시지 + 종료 코드 1 확인 |
| 카테고리 삭제 보호 | 사용 중 카테고리 삭제 차단 확인 |
| 예산 초과 경고 | 사용률 185%, 경고 문구 출력 확인 |
| 스택트레이스 미노출 / 종료 코드 규칙 | 모든 오류 케이스에서 `[오류]`/`[힌트]`만 출력, 실패 시 종료 코드 1 |
| CSV import/export 스키마 | `export_예시.csv`/`import_예시.csv`로 스키마 확인 |

# B2-1 평가자 질문 답변

## Figma Slides

[Figma에서 발표 자료 열기](https://www.figma.com/slides/GbTHDlKNGOOqPApAY05nQL)

이 자료는 평가자 질문 4개 항목을 구현 코드와 시연 결과에 연결해 설명합니다. 현재 구현 동작과 개선 제안을 구분했습니다.

## 1. 기능 요구와 데이터 지속성

- 거래 추가·목록·검색·요약·CSV 가져오기/내보내기·수정·삭제 기능을 제공합니다.
- 분류와 예산도 각각 관리하며, 사용 중인 분류의 삭제를 차단하고 예산 사용률 및 초과 여부를 요약합니다.
- `cli.py`의 `_build_service`가 거래·분류·예산 저장소를 구성합니다. 기본 `data/` 아래 `transactions.jsonl`, `categories.jsonl`, `budgets.jsonl`에 저장하므로 프로그램을 재실행해도 파일에서 복원됩니다. `--data-dir`로 경로를 바꿀 수 있습니다.
- CSV 입출력은 헤더와 UTF-8을 사용합니다. CLI의 `handle_errors`는 오류를 사용자에게 출력하고 실패 시 종료 코드 1을 반환합니다.
- 시연 결과에는 예산 초과 표시, 사용 중 분류 삭제 차단, 가져오기 2건 성공/1건 건너뜀, 수정·삭제 오류 종료 코드 1 사례가 있습니다.

## 2. 모듈·클래스의 책임과 수정/삭제

- `cli.py`: 인자 파싱, 사용자 입출력, 서비스·저장소 조립
- `service.py`: 입력 검증과 거래·분류·예산 업무 규칙
- `repository.py`: JSONL 파일 읽기/쓰기. `TransactionRepository`, `CategoryStore`, `BudgetStore`가 각 데이터 저장을 담당
- `models.py`: `Transaction` 자료 구조와 `to_dict`/`from_dict` 직렬화
- 거래 수정/삭제는 기존 파일을 순회해 임시 파일에 변경 내용을 기록한 후 `os.replace`로 교체합니다. 중간 쓰기 오류가 원본을 바로 덮어쓰는 위험을 줄이는 방식입니다. 다만 동시 쓰기 제어나 백업까지 제공하는 데이터베이스 트랜잭션은 아닙니다.

## 3. 제너레이터·장식자·타입 힌트

- `repository.py`의 `_read_jsonl`은 파일을 한 줄씩 읽어 `yield`하고 `iter_all()`도 순회 가능한 레코드를 전달합니다. 따라서 호출자가 원본 전체를 한 번에 메모리에 올릴 필요가 없습니다.
- 단, 검색은 일치 결과를 리스트에 모아 역순 처리하므로 결과 수에 비례하는 메모리를 사용합니다. “모든 조회가 상수 메모리”라고 설명하면 정확하지 않습니다.
- `decorators.py`의 `log_execution`은 실행 시각·함수·성공 여부·소요 시간을 `budget_app.log`에 기록합니다. `handle_errors`는 예외를 사용자용 메시지로 처리하고 실패 코드를 반환합니다.
- 타입 힌트 예: `TransactionRepository.iter_all() -> Iterator[Transaction]`. 반환 의도를 명확하게 해 IDE 자동완성과 정적 분석에 도움을 줍니다. 타입 힌트 자체가 실행 시 타입을 강제하지는 않습니다.

## 4. JSONL/CSV 선택, 대량 처리와 잘못된 행

- JSONL은 한 줄이 한 레코드라 내부 데이터의 순차 추가·읽기와 구조 확장에 편리합니다. 색인이 없으므로 검색·요약은 전체 순회가 필요합니다.
- CSV는 스프레드시트 호환성이 좋아 가져오기/내보내기에 적합하지만 헤더·인코딩·입력 검증 규칙이 필요합니다.
- 10만 건 규모에서는 `next_id()`가 추가 때마다 기존 거래를 다시 훑고, 목록/검색/요약은 전체 순회하며, 수정/삭제는 파일 전체를 다시 씁니다. ID 카운터, 조회 인덱스, SQLite 같은 DB, 대량 가져오기 배치 처리와 성능 측정을 개선안으로 검토할 수 있습니다.
- 현재 CSV 가져오기는 행 단위로 처리합니다. `AppError` 또는 필수 키 누락 행은 건너뛰고 유효한 행은 즉시 저장하므로 부분 성공 방식이며, 전체 롤백은 하지 않습니다. 현재 결과는 성공/건너뜀 건수 중심입니다. 개선안으로 행 번호·실패 사유 보고, 미리보기/검증 모드, 필요 시 임시 저장 후 일괄 교체를 제안합니다.

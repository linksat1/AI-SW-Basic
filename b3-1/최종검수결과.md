## 3. 기능 요구 사항 상세 대조

### 3-1. 기본 자료구조 직접 구현

| 요구사항 | 확인 방법 | 결과 |
|---|---|---|
| 이중 연결 리스트: `prev/next/data` 필드 | `linked_list.py: Node` | ✅ |
| `insert_front / insert_back / remove_front / remove_back / remove_node / move_to_front` 전부 구현, 전부 O(1) | 코드 리뷰 + 단위 테스트(생성→이동→삭제 순서 검증) | ✅ |
| 해시맵: `put/get/remove/contains/keys/size` | `hashmap.py` | ✅ |
| 해시 함수 직접 설계 | `_hash_string` (다항식 롤링 해시, h=h*31+ord(ch)) | ✅ |
| 충돌 해결 = 체이닝(이중 연결 리스트 재사용) | `hashmap.py`가 `linked_list.py`의 `DoublyLinkedList`를 버킷 체인으로 재사용 | ✅ |
| 로드 팩터 0.75 초과 시 버킷 2배 확장 | `_resize()` + 초기용량 4로 30개 강제 삽입 테스트, 8→...→32까지 여러 회 확장되며 전부 정상 조회 | ✅ |
| 힙: `push/pop/peek/size`, `_heapify_up/_heapify_down` | `heap.py` | ✅ |
| `(expire_at, key)` 요소 처리 | `store.py`의 `self._ttl_heap` 사용부 | ✅ |

### 3-2. String 명령어 세부 규칙

| 규칙 | 결과 |
|---|---|
| 키 기반 명령어는 실행 전 만료 여부 확인 (`_expire_if_needed`) | ✅ 모든 키 기반 메서드 첫머리에서 호출 |
| Redis 스타일 출력(OK/(nil)/(integer) N/(error) ...) | ✅ `cli.py`의 `fmt_*` 함수로 통일 |
| SET 성공 시 OK, 메모리 초과 시 LRU 제거 | ✅ results/02 |
| SET이 기존 키 덮어쓸 때 TTL 초기화 | ✅ results/06 (`EXPIRE k 100` 후 `SET k v2` → `TTL k` = -1) |
| GET: 없음/만료 시 (nil), 성공 시에만 LRU 갱신 | ✅ `store.py: get()` 코드 및 results/03 |
| DEL: 성공 1 / 없음 0, LRU·TTL 구조에서도 제거 | ✅ LRU는 즉시 제거(`_remove_key`→`_forget_lru`), TTL은 명세가 허용한 lazy deletion으로 처리 |
| EXISTS: 1/0 | ✅ results/01, 06 |
| DBSIZE: (integer) N | ✅ results/01, 05, 08 |
| KEYS: 배열 형태, 빈 경우 `(empty array)` | ✅ 빈 상태 별도 실행으로 확인(`(empty array)` 출력) |

### 3-3. 메모리 관리 + LRU 자동 제거

| 규칙 | 결과 |
|---|---|
| `CONFIG SET maxmemory bytes` (0=무제한, 파싱 실패 시 에러) | ✅ results/02, 04 |
| `INFO memory`가 used_memory/maxmemory/evicted_keys 출력 | ✅ results/02, 05 |
| `used_memory = Σ(len(utf8(key))+len(utf8(value)))` (구조 오버헤드 제외) | ✅ `_byte_len()` 함수로 정확히 구현, 과제 예시 수치(22)와 일치 |
| maxmemory 초과 시 LRU부터 제거, evicted_keys 누적 | ✅ results/02 (`evicted_keys:1`) |
| 단일 엔트리 자체가 maxmemory 초과 시 저장 안 하고 OOM | ✅ results/05 (`DBSIZE`=0, `used_memory`=0으로 부작용 없음 확인) |

### 3-4. TTL 관리(힙 기반)

| 규칙 | 결과 |
|---|---|
| `EXPIRE`: 없는 키 0 / 0초 이하 즉시 만료(있었으면 1) / 정상 설정 1 | ✅ results/06 |
| `TTL`: 없는 키 -2 / TTL 없음 -1 / 있으면 남은 초 | ✅ results/03, 06 |
| 만료된 키는 GET 시 먼저 삭제 후 (nil), LRU 갱신 안 함 | ✅ `store.py: get()` 코드 검토 |
| SET 덮어쓸 때 TTL 초기화 | ✅ results/06 |
| EXPIRE를 없는 키에 호출 시 0 | ✅ results/06 |
| DEL은 데이터/TTL/LRU 모두 제거 (TTL은 명세가 허용한 lazy deletion) | ✅ |
| 힙으로 "가장 빠른 만료" 조회 | ✅ `_purge_expired_from_heap()`이 매 명령마다 O(1) peek로 확인 |

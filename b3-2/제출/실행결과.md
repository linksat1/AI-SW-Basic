# B3-2 Mini Git — 실행 결과 제출자료

`가이드.md`의 실행 시나리오를 실제로 실행한 결과입니다.
실행 환경: Python 3.9.6, 실행 위치: `b3-2/` (명령: `python main.py`)

모든 원본 캡처는 [`results/`](results/) 폴더에 시나리오별 텍스트 파일로 들어 있습니다.
커밋 hash는 SHA-1 기반으로 실행할 때마다 새로 생성되므로 과제 예시(`a1b2c3` 등)와
실제 값은 다르지만, **구조와 흐름은 예시와 동일**합니다.

## 1. 저장소/브랜치 관리 (INIT/BRANCH/SWITCH/COMMIT)

([results/01_저장소_브랜치_관리.txt](results/01_저장소_브랜치_관리.txt))

```
mini-git> init "Alice"
Initialized repository.
Current branch: main
Current user: Alice
mini-git> commit "Initial commit"
[main 436c93] Initial commit
mini-git> branch feature
Created branch: feature
mini-git> switch feature
Switched to branch: feature
mini-git> commit "Add login feature"
[feature c3a878] Add login feature
mini-git> switch main
Switched to branch: main
mini-git> commit "Add payment feature"
[main a333a7] Add payment feature
```

과제 예시와 동일한 흐름(초기화 → 첫 커밋 → 브랜치 생성/전환 → 커밋 분기)이
정확히 재현되었습니다.

## 2. LOG (위상 정렬: 부모가 항상 자식보다 먼저)

([results/02_LOG_위상정렬.txt](results/02_LOG_위상정렬.txt))

```
commit 7e89e0 (Alice, 2026-07-12 16:22:21) [main]
Initial commit
commit 6cb31d (Alice, 2026-07-12 16:22:22) [feature]
Add login feature
commit c9757d (Alice, 2026-07-12 16:22:22) [main]
Add payment feature
```

"최신순"이 아니라 "부모가 먼저"라는 규칙대로, 뿌리 커밋(Initial commit)이
항상 맨 앞에 오고 그 두 자식(feature/main 분기)이 뒤따릅니다. 내부적으로는
Kahn의 위상 정렬 알고리즘(`traversal.topological_order`)을 사용했습니다.

## 3. LOG --sort-by=date / --sort-by=author

([results/03_LOG_정렬옵션.txt](results/03_LOG_정렬옵션.txt))

```
mini-git> log --sort-by=date
commit ab99e7 (Alice, 2026-07-12 16:22:23) [main]      Initial commit
commit 2e9dbb (Alice, 2026-07-12 16:22:23) [feature]   Add login feature
commit 55a8f3 (Alice, 2026-07-12 16:22:24) [main]      Add payment feature

mini-git> log --sort-by=author
(Alice 한 명뿐이라 동률 → 안정 정렬 규칙에 따라 원래(위상) 순서 그대로 유지됨)

mini-git> log --sort-by=invalidkey
Invalid args
```

`date`/`author` 둘 다 직접 구현한 병합 정렬(`sorting.merge_sort`)로 처리됩니다.
이 CLI는 세션당 사용자가 하나뿐이라 `--sort-by=author`의 시각적 차이를
REPL만으로 보여주기 어려워, 병합 정렬 자체의 정확성/안정성은 별도
단위 테스트로 여러 작성자·시각을 가진 가짜 커밋을 만들어 검증했습니다
(§7 참고). 지원하지 않는 정렬 기준(`invalidkey`)은 `Invalid args`로 처리됩니다.

## 4. PATH (최단 경로 — 직접 / 간접 / 자기 자신)

([results/04_PATH_최단경로.txt](results/04_PATH_최단경로.txt))

```
mini-git> path df9d44 d4b9b0
Path: df9d44 -> d4b9b0
mini-git> path 246016 d4b9b0
Path: 246016 -> df9d44 -> d4b9b0
mini-git> path df9d44 df9d44
Path: df9d44
```

- `Initial → Payment`: 둘이 부모-자식으로 바로 연결되어 있어 경로 길이 1
- `Login → Payment`: 직접 연결은 없지만 공통 부모(Initial)를 거쳐 무방향
  간선으로 2칸 만에 도달(`Login -> Initial -> Payment`)
- 자기 자신에 대한 PATH는 자기 자신 하나만 있는 경로

사전순 최소 경로 선택 로직(여러 최단 경로 중 문자열이 가장 작은 것 선택)은
다이아몬드형 그래프를 만들어 별도 단위 테스트로 정밀 검증했습니다(§7 참고).

## 5. ANCESTORS

([results/05_ANCESTORS.txt](results/05_ANCESTORS.txt))

```
mini-git> ancestors f3786b
Ancestors of f3786b:
- b9d0e3
mini-git> ancestors b9d0e3
No ancestors.
```

`Payment` 커밋의 조상은 `Initial` 하나뿐이고, 뿌리 커밋인 `Initial` 자신은
조상이 없어 `No ancestors.`를 정확히 반환합니다.

## 6. SEARCH (keyword / --author=)

([results/06_SEARCH.txt](results/06_SEARCH.txt))

```
mini-git> search login
Found 1 commit:

- ab5fbc: Add login feature

mini-git> search --author=Alice
Found 3 commits:

- 4b6ac6: Initial commit
- ab5fbc: Add login feature
- b82f26: Add payment feature

mini-git> search nosuchword
Found 0 commits:
```

과제 예시(`search "login"` → 1건)와 동일한 결과이며, 작성자 검색과
결과 없음(0건) 케이스도 정상 동작합니다. 두 검색 모두 전체 커밋을
순회하지 않고 역색인(`InvertedIndex`)에서 바로 조회합니다.

## 데이터 구조/알고리즘 자체 단위 검증 (보충)

REPL 실행과는 별개로, `mini_git/sorting.py`·`traversal.py`·`index.py`를 직접
import해 아래를 확인했습니다.

- **merge_sort**: 서로 다른 작성자 3명(Charlie/Alice/Bob/Alice)·시각을 가진
  가짜 커밋 4개를 만들어 `date`/`author` 두 키로 각각 정렬 → 결과가 기대한
  순서와 정확히 일치. 같은 작성자(Alice) 두 명의 상대적 순서가 원본 그대로
  유지되어 **안정 정렬임을 확인**. 원본 리스트가 변형되지 않음(제자리 정렬이
  아님)도 확인. 무작위 정수 1,000개를 정렬해 파이썬 `sorted()`(검증 전용으로만
  사용, 구현에는 미사용)와 결과가 완전히 일치함을 확인
- **traversal.shortest_path**: `root`에서 두 브랜치(`b1→c1`, `b2→c2`)가
  `merge` 커밋(부모 2개)으로 합쳐지는 다이아몬드형 그래프를 만들어, 동일한
  길이(3)의 두 경로 중 사전순으로 더 작은 `root→b1→c1→merge`가 정확히
  선택됨을 확인. 연결되지 않은 커밋 사이는 `None`(No path) 반환 확인
- **traversal.ancestors**: 위 다이아몬드 그래프의 `merge`에서 조상을 구하면
  `{b1, b2, c1, c2, root}` 5개가 중복 없이 모두 나옴을 확인(병합 커밋이라
  여러 경로로 같은 조상에 도달해도 한 번만 집계됨)
- **traversal.topological_order**: 위 그래프에서 `root`가 항상 `b1`/`b2`보다,
  `b1`/`b2`가 `c1`/`c2`보다, `c1`/`c2`가 `merge`보다 먼저 나오는지 확인
- **InvertedIndex**: 대소문자가 섞인 메시지("Add Login Feature")도 소문자로
  정규화되어 검색되는지("Login"으로 검색해도 매칭), 없는 키워드/작성자는
  빈 리스트를 반환하는지 확인

모두 예외 없이 통과했습니다.

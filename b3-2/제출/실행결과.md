## 이번에 수정한 동작

- `COMMIT "login login LOGIN"` 뒤 `SEARCH login`은 커밋 1개를 한 번만 출력합니다.
- `SEARCH "login feature"`는 연속된 단어 구문을 검색합니다. 대소문자와 공백 수는
  무시하지만 단어의 순서와 반복 횟수는 구분합니다. 부분 문자열 검색은 하지 않습니다.
- 구문 검색은 가장 드문 단어의 역색인 후보만 검사합니다. 전체 커밋 저장소의
  순회가 발생하면 실패하는 회귀 테스트로 단어·구문·작성자 검색을 확인했습니다.
- 기존 브랜치 이름으로 `BRANCH`를 실행하면 `Invalid args`를 출력하고
  모든 브랜치의 HEAD를 보존합니다.
- 공백뿐인 사용자명·브랜치명·메시지·검색어·작성자는 `Invalid args`로 거부합니다.
- ANCESTORS는 리스트 큐를 인덱스로 읽어 앞 원소 삭제 비용을 제거했습니다.

## 알고리즘 검증

- 고정 seed로 만든 DAG 50개에서 모든 부모·자식의 LOG 순서를 검증했습니다.
- DAG별 조상 목록은 별도 스택 탐색 결과와 대조하여 누락·중복을 확인했습니다.
- 최단 경로는 작은 그래프의 모든 단순 경로를 열거한 독립 검증 결과와 대조했습니다.
  길이를 우선 비교하고, 동률이면 `hash1->hash2->...` 문자열을 비교합니다.
- 다이아몬드형 다중 부모 그래프에서 사전순 최소 경로와 조상 합집합을 확인했습니다.
- 부모가 5,000개인 노드에서도 모든 조상이 중복 없이 반환되었습니다.
- 날짜·작성자 정렬과 같은 키의 안정성을 확인했습니다. 최대 1,000개 무작위 데이터로
  순서·원소 보존·원본 불변을 확인했으며, 테스트에도 표준 정렬 API를 사용하지 않았습니다.
- SHA-1 충돌을 강제로 발생시켜 이미 사용 중인 hash를 재사용하지 않는지 확인했습니다.
- 실제 구현의 AST를 검사해 `sorted()`와 `.sort()` 호출이 없음을 확인했습니다.

## 범위

Diff, Merge 명령, 복수 정렬 알고리즘 성능 비교는 선택 과제로 구현하지 않았습니다.
다중 부모 그래프 검증은 테스트에서 직접 구성합니다. CLI에는 MERGE 명령이 없습니다.
저장소 상태는 메모리에만 유지되며, INIT 재실행 시 커밋·브랜치·색인이 초기화됩니다.

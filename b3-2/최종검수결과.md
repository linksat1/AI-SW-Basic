# B3-2 Mini Git — 최종 검수 결과

`과제` 원문의 요구사항을 `mini_git/` + `main.py` 구현체와 `제출/results/`
실행 로그를 근거로 하나씩 대조한 최종 검수 기록입니다. 검수 일자 기준
실행 환경은 Python 3.9.6, 실행 위치 `b3-2/`(`python main.py`)입니다.

## 3. 기능 요구 사항 상세 대조

### 3-1. CLI 공통 규칙

| 요구사항 | 확인 방법 | 결과 |
|---|---|---|
| 명령어 대소문자 무관 | `cli.py: dispatch()`의 `tokens[0].upper()` + results/08 (`INIT`/`Commit`/`BRANCH`/`Switch`/`LOG` 혼용 실행) | ✅ |
| 공백 포함 문자열 인자는 따옴표로 감싸 지원 | `shlex.split()` 사용, 전 결과 파일에서 `"Add login feature"` 등 정상 파싱 | ✅ |
| 옵션 표기 `--author=`, `--sort-by=` | `cli.py`의 `_cmd_search`/`_cmd_log`에서 `startswith("--...=")` 파싱 | ✅ |
| 표준 에러: Invalid args / Unknown branch / Unknown commit | `errors.py` 3개 예외 클래스 + results/07 (문구까지 정확히 일치) | ✅ |

### 3-2. 커밋 그래프(핵심 자료구조)

| 요구사항 | 확인 방법 | 결과 |
|---|---|---|
| 커밋 노드 최소 필드(hash/message/author/timestamp/parents) | `commit.py: Commit.__init__` | ✅ |
| 0개 이상의 부모 | `parents` 리스트, 0개(뿌리)/1개(일반)/2개(병합, 구조상 지원) 모두 처리 | ✅ |
| DAG 구조 | 부모만 참조하는 단방향 구조라 구조적으로 사이클 불가 (평가질문 2장에서 논증) | ✅ |
| hash로 빠르게 찾기(해시맵 기반) | `Repository.commits`가 `dict`(hash→Commit) | ✅ |
| hash 세션 내 유일성 보장 | `commit.py: generate_commit_hash()` — SHA-1 + 세션 카운터 + 충돌 시 재시도 방어 로직 | ✅ |

### 3-3. 역색인(Inverted Index)

| 요구사항 | 확인 방법 | 결과 |
|---|---|---|
| 순회 없이 후보를 빠르게 조회 | `index.py`가 dict 조회(O(1))만 수행, 전체 커밋 순회 없음 | ✅ |
| 키워드 추출: 공백 split + lower 정규화 | `index.py: add_commit()`의 `message.split()` + `.lower()` | ✅ |
| keyword → commit_hash 목록 | `_keyword_index` | ✅ |
| author → commit_hash 목록 | `_author_index` | ✅ |

### 3-4. 정렬 알고리즘 직접 구현

| 요구사항 | 확인 방법 | 결과 |
|---|---|---|
| `sorted()`/`list.sort()` 사용 금지 | `main.py`, `mini_git/*.py` 전체 grep 전수 검사 — 실사용 0건 | ✅ |
| 비교 기준을 바꿔 정렬 가능 | `merge_sort(items, key)` — `key` 함수로 date/author 등 자유 지정 | ✅ |

### 3-5. 명령어별 기능

| 명령어 | 세부 규칙 | 결과 |

## 5. 보너스 과제

Diff / Merge(브랜치 병합) / 정렬 알고리즘 성능 비교 3개 모두 **선택
사항이며 이번 제출에는 포함하지 않았습니다.** 필수 요구사항을 확실히
완성하는 데 우선순위를 두었습니다(사유는 `가이드.md` 6-1절에 기재).
다만 `traversal.py`의 세 알고리즘은 부모가 2개(병합 커밋)여도 그대로
동작하도록 이미 일반적으로 작성해, 보너스 2번(Merge)을 이어서 구현할
때 탐색 로직 수정이 필요 없는 구조임을 단위 테스트로 확인했습니다.

## 2. 최종 설명 (리뷰 문서)

**Improve b3-2 AI code description helper to meet all requirements**

### Summary
- 기존 `describe`의 미충족 요구사항을 채워, Git 수집부터 검증된 설명 출력까지 한 번에 동작하고 API 실패 원인을 구분해 알려줍니다.
- 형식 오류는 1회 재생성과 후처리로 보정하고, 팀 컨벤션과 safe-mode 정책을 설정으로 바꿀 수 있습니다.

### What Changed
- `ai_code_desc/ai_client.py`: SDK 예외(401/403/404/429/5xx/시간 초과/연결 실패/refusal)를 원인 메시지로 변환하고, 기본 모델 `claude-opus-5-5`와 `--effort`를 적용했습니다.
- `ai_code_desc/cli.py`, `generator.py`: 검증 실패 시 피드백 재생성(최대 2회 호출) → 후처리 보정을 하고, 진행 로그와 호출 횟수를 출력합니다.
- `ai_code_desc/git_context.py`, `safe_mode.py`, `convention.py`: 새 파일 diff 수집, 루트 실행 검사, 정규식 마스킹 확장, 파일/줄 제한, JSON 컨벤션을 추가했습니다.

### Why It Was Needed
- 이전 구현은 실제 API 실패 시 traceback을 출력하고, 검증에 실패해도 보정하지 않아 과제 필수 요구사항을 채우지 못했습니다.
- `--mock`이 `--intent`를 무시하고 새 파일 내용을 빠뜨려, 시연 결과가 실제 변경과 맞지 않았습니다.

### How to Verify
- `python3 -B -m unittest discover -s tests -v` (27개 통과)
- `제출/results/04_API_인증실패.txt`의 401 메시지와 `11_실제API_설명생성.txt`의 실제 생성 결과를 확인합니다.

## 3. AI 초안 → 최종 설명 변경점

1. **제목**: AI는 "새 CLI 추가(Add)"로 썼습니다. 이 브랜치의 기존 구현을 보완한 변경이므로 `Improve ... to meet all requirements`로 바꿨습니다.
2. **원인 분석**: safe-mode가 경로순 앞 10개 파일만 보내면서 `.gitignore`, `README.md` 같은 문서만 전달됐고, 핵심 코드는 AI에 전달되지 않았습니다. AI가 이 사실을 스스로 밝히고 "확인 필요"라고 적은 점은 의도한 프롬프트 규칙대로입니다.
3. **What Changed**: README·.gitignore 중심이던 불릿을, 실제 로직이 바뀐 모듈과 변경 내용으로 바꿨습니다. "확인 필요"로 남은 부분은 직접 diff를 보고 채웠습니다.
4. **Why It Was Needed**: 초안은 수정 의도를 다시 쓴 수준이었습니다. 이전 구현의 구체적인 문제(traceback, 보정 없음, mock 의도 무시)를 근거로 바꿨습니다.
5. **How to Verify**: 테스트 개수를 실제 값(27개)으로 고쳤습니다. 검증기 수정 테스트가 추가되기 전의 README 값(26개)을 AI가 인용했기 때문입니다. 실제 생성 결과 증빙(results/11)도 추가했습니다.
6. **유지한 부분**: 팀 컨벤션(영어 명령형 제목, `파일 경로: 내용` 형식, 백틱 명령)은 AI가 잘 따라서 형식은 그대로 썼습니다. `--mock`/`--dry-run` 검증 명령도 유지했습니다.
7. **도구 개선**: 이 실행에서 하위 불릿까지 개수에 세는 검증기 오류를 발견해 고쳤습니다(테스트 추가). 큰 변경에서는 `--max-files`를 늘리거나 변경을 나눠 실행해야 한다는 점을 README 6장에 적었습니다.

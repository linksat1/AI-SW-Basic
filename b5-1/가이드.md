## 1. 과제 개요

**만들어야 하는 것**: 백엔드 프레임워크 없이, SQL만으로 완성하는 나만의 데이터베이스

**완성 기준**:
- [ ] 자유 주제로 테이블 4개 이상 설계 (1:N 관계 2개 이상 포함)
- [ ] 스키마 생성 스크립트 1개 (`CREATE TABLE`, PK/FK/제약조건 포함)
- [ ] 샘플 데이터 입력 스크립트 1개 (테이블당 최소 10행)
- [ ] 핵심 쿼리 15개 + 실행 결과 캡처

**폴더 구조** (이 저장소 기준):
```
b5-1/
├── 가이드.md              ← 지금 보고 있는 이 문서
├── 과제                    ← 채점 기준이 담긴 원본 과제 요구사항 (참고용, 수정 X)
└── 예제/                  ← 먼저 따라 실행해볼 완성된 예제 (도서 대여 주제)
    ├── 01_schema.sql
    ├── 02_data.sql
    └── 03_queries.sql
```

> **진행 순서 추천**: 3장의 예제를 먼저 그대로 실행해서 "이게 어떻게 동작하는지" 감을 잡은 다음,
> 4장에서 안내하는 대로 `제출/` 폴더를 직접 새로 만들어 내 주제로 채웁니다.
> (제출용 폴더는 미리 만들어두지 않았습니다 — 빈 템플릿을 그대로 베끼는 것보다,
> 예제를 참고해서 직접 파일을 만들어보는 편이 학습에 더 도움이 됩니다.)

## 2. 개발 환경 준비

DB는 SQLite, 도구는 **DB Browser for SQLite**를 추천합니다. 서버 설치가 필요 없고 파일 하나로 끝나서 입문자에게 가장 쉽습니다.

### 2-1. DB Browser for SQLite 설치 (GUI 도구, 추천)

1. https://sqlitebrowser.org/dl/ 접속
2. **Windows**: `DB Browser for SQLite - Standard installer for 64-bit Windows` 다운로드 후 설치
   (대부분의 개인 PC는 64비트입니다. `설정 > 시스템 > 정보`에서 "시스템 종류"로 확인 가능)
   **macOS(공용 PC)**: `DB Browser for SQLite - Standard installer for macOS` 다운로드 후 설치
   (Linux는 배포판에 맞는 패키지 선택)
3. 설치 후 실행하면 "New Database", "Open Database", "Execute SQL" 탭이 보이는 프로그램이 열립니다.

### 2-2. (선택) 터미널에서 sqlite3 CLI 사용하기

**macOS(공용 PC)**: 기본적으로 `sqlite3` 명령어가 설치되어 있습니다. 터미널에서 확인:

```bash
sqlite3 --version
```

버전이 출력되면 바로 사용 가능합니다. 만약 없다면 (Homebrew 설치):

```bash
brew install sqlite3
```

**Windows(개인 PC)**: 기본적으로 설치되어 있지 않습니다. PowerShell을 열고 winget으로 설치:

```powershell
winget install SQLite.SQLite
```

설치 후 **반드시 지금 열려 있는 PowerShell 창을 완전히 닫고 새로 열어서** 확인해야 합니다.
(winget이 PATH를 갱신해도 이미 열려 있던 창에는 반영되지 않아 `sqlite3` 명령을 못 찾는다는 에러가 납니다.)

```powershell
sqlite3 --version
```

버전 정보가 출력되면 설치 성공입니다. `winget`이 안 되거나 새 창에서도 버전 확인이 안 되면, https://sqlite.org/download.html 에서
"Precompiled Binaries for Windows" 섹션의 `sqlite-tools-win-x64-*.zip`을 받아 압축을 풀고,
그 폴더 경로를 환경 변수 PATH에 추가하면 됩니다.

> GUI(DB Browser)와 CLI(sqlite3) 중 편한 쪽 하나만 써도 충분합니다.
> 이 가이드는 두 가지 방법을 모두 안내합니다. CLI 설치가 번거롭다면 방법 B(GUI)만 사용해도 과제 진행에 전혀 문제없습니다.

## 3. 예제로 먼저 따라해보기

`b5-1/예제/` 폴더에는 **"도서 대여" 주제로 완성된 예제**가 이미 들어있습니다.
이 예제를 그대로 실행해보면서 스키마 → 데이터 → 쿼리가 어떻게 이어지는지 눈으로 확인합니다.

### 방법 A) 터미널(sqlite3 CLI)로 실행하기

**macOS(공용 PC) — 터미널**

```bash
# 1. 예제 폴더로 이동
cd b5-1/예제

# 2. 새 DB 파일을 만들면서 스키마 적용
sqlite3 example.db < 01_schema.sql

# 3. 샘플 데이터 입력
sqlite3 example.db < 02_data.sql

# 4. 쿼리 15개 실행 (결과가 표 형태로 보기 좋게 출력됨)
sqlite3 -header -column example.db < 03_queries.sql
```

**Windows(개인 PC) — PowerShell**

PowerShell은 `<` 리다이렉션을 지원하지 않으므로 `Get-Content`로 파일 내용을 넘겨줍니다.

> ⚠️ **중요**: `Get-Content`에 반드시 `-Encoding UTF8`을 붙이세요. 이걸 빠뜨리면 `.sql` 파일 안의 한글 주석 때문에
> 인코딩이 깨지면서 단순히 글자가 깨지는 정도가 아니라 **`CREATE TABLE`의 일부 컬럼이 통째로 누락되는** 등
> 조용히(에러 없이) 스키마가 잘못 만들어질 수 있습니다. `-Encoding UTF8`을 빼먹고 실행했다가 나중에
> "컬럼이 없다"는 에러를 만나면 이 문제를 의심하세요.

```powershell
# 1. 예제 폴더로 이동
cd b5-1\예제

# 2. 새 DB 파일을 만들면서 스키마 적용
Get-Content -Encoding UTF8 01_schema.sql | sqlite3 example.db

# 3. 샘플 데이터 입력
Get-Content -Encoding UTF8 02_data.sql | sqlite3 example.db

# 4. 쿼리 15개 실행 (결과가 표 형태로 보기 좋게 출력됨)
Get-Content -Encoding UTF8 03_queries.sql | sqlite3 -header -column example.db
```

> 참고: Windows 명령 프롬프트(cmd.exe)를 쓴다면 macOS와 동일하게 `sqlite3 example.db < 01_schema.sql` 형태의 `<` 리다이렉션이 그대로 동작합니다.

터미널(또는 PowerShell)에 표 형태로 조회 결과가 쭉 출력되면 성공입니다.

### 방법 B) DB Browser for SQLite(GUI)로 실행하기

1. DB Browser for SQLite 실행 → **New Database** 클릭
2. 저장 위치를 `b5-1/예제/example.db` 로 지정하고 저장 (테이블 만들기 창이 뜨면 **Cancel**로 닫기)
3. 상단 **Execute SQL** 탭 클릭
4. `01_schema.sql` 파일 내용을 열어(메모장/VS Code) 전체 복사 → Execute SQL 탭에 붙여넣기 → 재생▶ 버튼(또는 Ctrl+Enter) 클릭
5. 같은 방식으로 `02_data.sql` 내용을 붙여넣고 실행
6. **Browse Data** 탭 → 상단 드롭다운에서 `member`, `book`, `rental` 등을 선택해 데이터가 들어갔는지 확인
7. 다시 **Execute SQL** 탭에서 `03_queries.sql`의 쿼리를 하나씩 붙여넣고 실행하며 결과 확인

> **왜 예제를 먼저 실행해보나요?**
> 스키마 파일 하나만 봐서는 관계가 잘 안 잡힙니다. 실제로 실행해서
> "카테고리에 책이 연결되고, 회원과 책이 대여 기록으로 연결된다"는 흐름을 눈으로 보면
> 내 주제를 설계할 때 훨씬 감이 잡힙니다.

### 예제 구조 한눈에 보기

| 테이블 | 역할 | 연결된 FK |
|---|---|---|
| `category` | 도서 분류 (부모) | - |
| `member` | 회원 (부모) | - |
| `book` | 도서, `category`를 참조 | `book.category_id → category.id` |
| `rental` | 대여 기록, `member`/`book`을 참조 | `rental.member_id → member.id`, `rental.book_id → book.id` |

`category → book`, `member → rental`, `book → rental` 총 3개의 1:N 관계가 있어 과제 요구사항(2개 이상)을 충족합니다.

### 4-1. 주제 정하기

과제에서 제안하는 예시 중 하나를 고르거나 자유 주제를 정합니다.

| 주제 | 테이블 예시 |
|---|---|
| 카페 주문 | customer, menu, order, order_item |
| 영화 평점 | user, movie, review, genre |
| 온라인 쇼핑 | member, product, order, order_item |
| 학급 관리 | student, subject, grade, teacher |

> 팁: 처음이라면 예제와 비슷한 구조(부모 테이블 2개 + 그걸 참조하는 자식 테이블 1~2개)로
> 시작하는 게 안전합니다. 표를 그려보고 어떤 테이블이 어떤 테이블을 참조하는지 화살표로
> 먼저 적어본 다음 SQL로 옮기세요.

### 4-2. 테이블 설계 (종이/메모에 먼저 정리)

각 테이블마다 아래를 정합니다.

- 테이블 이름 (역할이 드러나게: `student`, `order_item` 등)
- 컬럼 목록과 타입 (`TEXT`, `INTEGER`, `DATE` 등)
- PK (보통 `id INTEGER PRIMARY KEY AUTOINCREMENT`)
- FK (다른 테이블의 PK를 참조하는 컬럼, `1:N`의 "N" 쪽 테이블에 위치)
- NOT NULL을 걸 컬럼 (최소 1개)
- UNIQUE를 걸 컬럼 (최소 1개, 예: 이메일, 학번)

### 4-3. `제출/schema.sql` 작성

`예제/01_schema.sql`을 참고해서 `제출/schema.sql`을 채웁니다.

```sql
PRAGMA foreign_keys = ON;   -- SQLite는 이 줄이 없으면 FK 제약이 무시됨 (중요)

CREATE TABLE category (
    id   INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL UNIQUE
);

CREATE TABLE book (
    id             INTEGER PRIMARY KEY AUTOINCREMENT,
    title          TEXT NOT NULL,
    category_id    INTEGER NOT NULL,
    FOREIGN KEY (category_id) REFERENCES category(id)
);

CREATE INDEX idx_book_category_id ON book(category_id);
```

작성 후 실행해서 에러 없이 테이블이 만들어지는지 확인합니다.

```bash
# macOS
sqlite3 mydb.db < 제출/schema.sql
```

```powershell
# Windows(PowerShell)
Get-Content -Encoding UTF8 제출\schema.sql | sqlite3 mydb.db
```

### 4-4. `제출/data.sql` 작성

**순서가 중요합니다.** FK가 참조하는 부모 테이블 데이터를 먼저 넣어야 합니다.
예: `book`에 데이터를 넣기 전에 `category`에 먼저 데이터가 있어야 합니다.

각 테이블에 **최소 10행**씩 넣습니다. (`예제/02_data.sql` 형식 참고)

```bash
# macOS
sqlite3 mydb.db < 제출/data.sql
```

```powershell
# Windows(PowerShell)
Get-Content -Encoding UTF8 제출\data.sql | sqlite3 mydb.db
```

만약 다음과 같은 에러가 나면 부모 데이터가 없는 상태에서 자식 데이터를 넣은 것입니다.

```
FOREIGN KEY constraint failed
```

→ INSERT 순서를 다시 확인하세요.

### 4-5. `제출/queries.sql` 작성

`예제/03_queries.sql`을 열어 각 쿼리 위의 `-- [카테고리]` 주석과 쿼리 구조를 그대로 참고하면서,
내 테이블/컬럼 이름에 맞게 바꿔 `제출/queries.sql`에 15개를 채워 넣습니다.
아래 표의 개수를 모두 충족해야 합니다.

| # | 카테고리 | 최소 개수 | 예제 파일에서 참고할 위치 |
|---|---|---|---|
| 1 | 기본조회 (WHERE/ORDER BY/LIMIT) | 4개 | `[기본조회 1~4]` |
| 2 | 조인 (INNER 2개↑, LEFT 1개↑) | 4개 | `[조인-INNER 1~3]`, `[조인-LEFT 1]` |
| 3 | 집계 (COUNT/SUM/AVG 중 2개↑ + GROUP BY) | 3개 | `[집계 1~3]` |
| 4 | 서브쿼리 | 1개 | `[서브쿼리]` |
| 5 | UPDATE/DELETE | 2개 | `[수정 UPDATE]`, `[삭제 DELETE]` |
| 6 | 인덱스 (+ 적용 이유 1줄) | 1개 | `[인덱스]` |

각 쿼리 바로 위에 "이 쿼리가 무엇을 확인하는지" 한 줄 주석을 꼭 남기세요. (`예제/03_queries.sql`처럼)

## 5. 실행 결과 캡처하는 법

### DB Browser for SQLite 사용 시
1. **Execute SQL** 탭에 쿼리 하나를 붙여넣고 실행
2. 하단에 나온 결과 표가 화면에 보이는 상태에서 스크린샷
   (macOS: `Cmd+Shift+4` / Windows: `Win+Shift+S`로 캡처 도구 실행 후 영역 선택 → 붙여넣기(Ctrl+V)로 그림판 등에 저장)
3. 파일명은 쿼리 번호에 맞춰 저장 (예: `05_조인INNER1.png`)
4. `b5-1/제출/results/` 폴더에 저장

### sqlite3 CLI 사용 시
결과를 텍스트로도 남길 수 있습니다.

```bash
# macOS
sqlite3 -header -column mydb.db "SELECT ... ;" > 제출/results/05_조인INNER1.txt
```

```powershell
# Windows(PowerShell)
sqlite3 -header -column mydb.db "SELECT ... ;" | Out-File -Encoding utf8 제출\results\05_조인INNER1.txt
```

또는 터미널 화면을 스크린샷으로 남겨도 됩니다.

## 6. 제출물 체크리스트

- [ ] `제출/schema.sql` — CREATE TABLE, PK/FK/제약조건 포함, 실행 순서대로 정리됨
- [ ] `제출/data.sql` — 각 테이블 최소 10행, FK 관계가 실제로 연결됨
- [ ] `제출/queries.sql` — 쿼리 15개, 각 쿼리에 한 줄 설명 주석
- [ ] `제출/results/` — 쿼리별 실행 결과 캡처
- [ ] (선택) ERD 다이어그램 이미지 — [dbdiagram.io](https://dbdiagram.io) 또는 [draw.io](https://app.diagrams.net)에서 테이블 관계를 그려 이미지로 저장
- [ ] 스키마/데이터/쿼리 3개 파일을 순서대로 실행했을 때 에러 없이 끝까지 실행됨 (제출 전 반드시 처음부터 재실행해서 확인)

제출 직전 최종 점검 명령어:

**macOS(공용 PC)**

```bash
cd b5-1/제출
rm -f final_check.db
sqlite3 final_check.db < schema.sql
sqlite3 final_check.db < data.sql
sqlite3 -header -column final_check.db < queries.sql
```

**Windows(개인 PC) — PowerShell**

```powershell
cd b5-1\제출
Remove-Item -Force final_check.db -ErrorAction SilentlyContinue
Get-Content -Encoding UTF8 schema.sql | sqlite3 final_check.db
Get-Content -Encoding UTF8 data.sql | sqlite3 final_check.db
Get-Content -Encoding UTF8 queries.sql | sqlite3 -header -column final_check.db
```

에러 없이 끝까지 실행되면 준비 완료입니다. (`final_check.db`는 확인용이므로 이후 삭제해도 됩니다.)

## 7. 보너스 과제

여유가 있다면 아래도 도전해보세요.

1. **조인 vs 서브쿼리 비교**: 같은 요구사항을 INNER JOIN 버전과 서브쿼리 버전 두 가지로 작성하고, 어떤 차이가 있는지 한두 줄로 비교 기록
2. **정합성 깨뜨려보기**: 존재하지 않는 부모 id를 FK 컬럼에 넣어보고 (`FOREIGN KEY constraint failed` 에러 발생 확인) 왜 막히는지, 어떻게 고쳐야 하는지 기록
3. **미니 리포트**: 내 DB에서 뽑을 수 있는 핵심 지표 3개를 정의하고 각각 구하는 SQL 최종본 정리 (예: 월별 주문 건수 추이, 인기 TOP 10, 특정 조건 비율 등)

## 8. 자주 발생하는 문제 해결

### `FOREIGN KEY constraint failed`
- **원인 1**: `PRAGMA foreign_keys = ON;`을 스크립트 맨 앞에 넣지 않음
- **원인 2**: 자식 테이블(FK가 있는 테이블)에 데이터를 넣을 때, 참조하는 부모 데이터가 아직 없음
  → `data.sql`에서 INSERT 순서를 부모 → 자식 순으로 재배치

### `UNIQUE constraint failed`
- 같은 값을 UNIQUE 컬럼(예: email)에 두 번 이상 넣었을 때 발생
- 샘플 데이터에서 중복된 값이 없는지 확인

### DB Browser에서 "Execute SQL" 결과가 안 보임
- 여러 줄의 SQL을 한꺼번에 붙여넣었다면 상단 재생▶ 버튼 대신 **"Execute all"** 아이콘(▶▶ 모양)을 사용
- 하단 로그(Console) 창에 에러 메시지가 있는지 확인

### `no such column` / `table X has no column named Y` 에러가 스키마상 있는 컬럼인데도 발생함 (Windows)
- **원인**: `Get-Content`에 `-Encoding UTF8`을 빼먹었을 가능성이 매우 높습니다. `.sql` 파일에 한글 주석이 있으면
  `Get-Content`가 기본 인코딩(시스템 코드페이지)으로 잘못 읽어서, `CREATE TABLE` 중간의 일부 컬럼 정의가
  통째로 사라진 채로 테이블이 만들어집니다. **에러 없이 조용히** 잘못된 스키마가 생성되므로 알아채기 어렵습니다.
- **해결**: 모든 `Get-Content` 명령에 `-Encoding UTF8`을 붙였는지 확인하고, DB 파일을 지운 뒤 처음부터 다시 실행하세요.
  ```powershell
  Get-Content -Encoding UTF8 schema.sql | sqlite3 mydb.db
  ```
  실제로 만들어진 테이블 구조를 확인하려면:
  ```powershell
  sqlite3 mydb.db "PRAGMA table_info(테이블이름);"
  ```

### 결과 파일이 깨져 보임(한글 깨짐)
- 터미널 인코딩 문제일 수 있습니다.
- **macOS**: 기본 터미널은 UTF-8이라 보통 문제 없지만, 깨진다면 `export LANG=ko_KR.UTF-8` 실행 후 다시 시도
- **Windows**: PowerShell/cmd 콘솔이 기본적으로 UTF-8이 아닐 수 있습니다. 다음 명령으로 콘솔 코드페이지를 UTF-8로 바꾸고,
  `Get-Content`에는 항상 `-Encoding UTF8`을 붙이세요.
  ```powershell
  chcp 65001
  ```

### `sqlite3 --version` 명령이 안 먹힘
- **macOS**: 기본 제공 여부는 버전에 따라 다를 수 있습니다. `brew install sqlite3`로 설치하세요.
- **Windows**: 기본 제공되지 않습니다. `winget install SQLite.SQLite`로 설치 후 PowerShell을 새로 열어 다시 시도하세요. (2-2 참고)
- 둘 다 CLI 없이 DB Browser for SQLite(GUI)만 사용해도 과제 진행에 전혀 문제 없습니다.

### 쿼리 결과가 0건만 나옴
- WHERE 조건의 값(날짜, 상태 문자열 등)이 실제 데이터와 철자/형식이 맞는지 확인
- 예: `'2025-01-01'`처럼 날짜는 따옴표로 감싼 문자열 형식(YYYY-MM-DD)을 사용했는지 확인

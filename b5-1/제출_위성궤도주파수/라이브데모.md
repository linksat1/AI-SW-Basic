# 평가 당일 라이브 실행 순서

평가자 앞에서 "진짜 동작하는지" 직접 보여줄 때 그대로 복사/붙여넣기 하면 되는 순서입니다.
15개 쿼리를 전부 라이브로 돌리면 지루하니, **재현 검증(전체) + 대표 쿼리 6개(설명용) + 보너스 1개(가장 임팩트 있는 것)**만 실시간으로 보여주고,
나머지는 `results/` 폴더의 캡처로 대체하는 걸 추천합니다.

> **더 간단한 방법**: 노트북/터미널 세팅 없이 그냥 https://visuallsat.com/sql-demo/ 를 열어서
> 버튼으로 21개(15개+보너스 6개) 쿼리를 바로 보여줘도 됩니다. 이 문서는 "로컬 CLI로 직접
> 재현 가능하다"는 걸 보여주고 싶을 때(터미널/SQL 실력을 어필하고 싶을 때) 쓰는 버전입니다.

## 1. 재현 검증 — "처음부터 다시 돌려도 에러 없이 된다" (1분)

**말할 것**: "지금 이 자리에서 DB 파일을 지우고 스키마부터 새로 만들어 보이겠습니다."

```powershell
Remove-Item -Force live.db -ErrorAction SilentlyContinue
Get-Content -Encoding UTF8 schema.sql | sqlite3 live.db
Get-Content -Encoding UTF8 data.sql | sqlite3 live.db
sqlite3 live.db "SELECT 'notice',COUNT(*) FROM notice UNION ALL SELECT 'geo',COUNT(*) FROM geo UNION ALL SELECT 'orbit',COUNT(*) FROM orbit UNION ALL SELECT 'freq',COUNT(*) FROM freq;"
```

→ `notice 17 / geo 15 / orbit 26 / freq 50`이 나오면 성공. 에러 한 줄도 없이 끝났다는 걸 강조.

## 3. 대표 쿼리 6개 라이브 실행 (3~4분)

각 쿼리 실행 전에 "무엇을 확인하는 쿼리인지" 한 줄 말하고 실행하세요. (`평가질문_설명자료.md` 5~9장 설명과 그대로 연결됩니다.)

### ① 기본조회 — WHERE/ORDER BY/LIMIT
```powershell
sqlite3 -header -column live.db "SELECT ntc_id, adm, d_rcv FROM notice WHERE ntc_type='G' ORDER BY d_rcv DESC LIMIT 5;"
```

### ② INNER JOIN — 위성 이름 + 궤도 위치
```powershell
sqlite3 -header -column live.db "SELECT n.ntc_id, n.adm, g.sat_name, g.long_nom FROM notice n INNER JOIN geo g ON n.ntc_id=g.ntc_id ORDER BY g.long_nom;"
```

### ③ LEFT JOIN — 비정지궤도 신고는 geo가 NULL로 남는 것 보여주기 (INNER와 대비되는 핵심 포인트)
```powershell
sqlite3 -header -column live.db "SELECT n.ntc_id, n.adm, n.ntc_type, g.sat_name FROM notice n LEFT JOIN geo g ON n.ntc_id=g.ntc_id ORDER BY n.ntc_id;"
```

### ④ 집계 — 신고국별 건수 (COUNT + GROUP BY)
```powershell
sqlite3 -header -column live.db "SELECT adm, COUNT(*) AS 건수 FROM notice GROUP BY adm ORDER BY 건수 DESC;"
```

### ⑤ 서브쿼리 — 평균보다 넓은 대역
```powershell
sqlite3 -header -column live.db "SELECT ntc_id, freq_min, freq_max, bdwdth FROM freq WHERE bdwdth > (SELECT AVG(bdwdth) FROM freq) ORDER BY bdwdth DESC;"
```

### ⑥ 인덱스 — 실행계획으로 증명
```powershell
sqlite3 live.db "EXPLAIN QUERY PLAN SELECT n.adm, f.freq_min FROM notice n INNER JOIN freq f ON n.ntc_id=f.ntc_id WHERE f.ntc_id=125520109;"
```
→ `SEARCH f USING INDEX idx_freq_ntc_id (ntc_id=?)` 줄을 손가락으로 짚으며 "인덱스를 실제로 탔다"고 설명.

## 4. 보너스 라이브 시연 — FK 위반 재현 (가장 임팩트 있음, 1분)

**말할 것**: "정합성이 실제로 지켜지는지 일부러 깨뜨려 보겠습니다."

```powershell
sqlite3 live.db "PRAGMA foreign_keys = ON; INSERT INTO geo (ntc_id, sat_name, long_nom) VALUES (999999999, 'GHOST-SAT', 100);"
```

→ `Error: FOREIGN KEY constraint failed`가 그 자리에서 뜹니다. 이어서:

```powershell
sqlite3 live.db "SELECT COUNT(*) FROM geo WHERE sat_name='GHOST-SAT';"
```

→ `0`이 나오는 걸 보여주며 "실제로 안 들어갔다"고 마무리.

## 5. UPDATE/DELETE는 결과만 보여주기 (라이브로 굳이 다시 안 해도 됨)

이미 `data.sql` 원본과 `queries.sql`의 UPDATE/DELETE를 실행한 뒤의 `results/13_수정UPDATE.txt`,
`results/14_삭제DELETE.txt`가 있으므로, 라이브에서 굳이 재현할 필요는 없습니다. 대신 SQL 코드만
화면에 띄우고 "WHERE 조건 없이 실행하면 전체가 바뀌기 때문에 항상 조건부터 확인한다"는 원칙을
한 줄 언급하면 충분합니다.

## 7. 라이브 중 문제가 생기면

- `sqlite3` 명령을 못 찾는다 → PowerShell을 새로 열었는지 확인, 또는 `winget install SQLite.SQLite` 재설치
- 한글이 깨지거나 컬럼이 없다는 에러 → `Get-Content -Encoding UTF8`을 빠뜨렸는지 확인
- `live.db`가 이미 있어서 `UNIQUE`/`PK` 에러가 난다 → `Remove-Item -Force live.db` 후 처음부터 재실행 (1번 단계부터 다시)

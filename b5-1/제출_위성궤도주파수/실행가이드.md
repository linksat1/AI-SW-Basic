# 과제 실행 가이드 — 위성 궤도/주파수 데이터베이스

이 폴더는 b5-1 "SQL로 만드는 나만의 데이터베이스" 과제의 제출물입니다.
주제는 **"위성 궤도/주파수"**이며, 실제 위성망 등록 DB_3075
데이터를 발췌해서 만들었습니다.

> **라이브 데모**: https://visuallsat.com/sql-demo/
> 아래 15개 쿼리 + 보너스 항목을 로컬에 설치 없이 브라우저에서 버튼으로 바로 실행해볼 수 있습니다.
> (백엔드: `b6-1/sql-demo-app/`, FastAPI. 버튼 클릭마다 서버에서 실제 SQL이 실행되며,
> 화이트리스트에 있는 고정 쿼리만 실행되므로 자유 SQL 입력·SQL 인젝션 위험은 없습니다.
> 초당 5건 · 버스트 10건으로 요청 속도도 제한되어 있어 스크립트로 한꺼번에 긁어가기 어렵습니다.)

**평가 후 SQL 원문 가리기**: 지금은 평가를 위해 각 쿼리 버튼 위에 "실행 SQL"이 그대로 보입니다.
평가가 끝나면 서버에 SSH로 접속해서 아래 두 줄만 실행하면, 코드 재배포 없이 SQL 텍스트가 즉시
API 응답에서 빠집니다 (쿼리 실행 자체는 계속 정상 동작합니다).

```bash
ssh -i <키페어_경로>.pem ec2-user@<EC2_퍼블릭IP>
sudo sed -i 's/SHOW_SQL=true/SHOW_SQL=false/' /etc/systemd/system/sql-demo.service
sudo systemctl daemon-reload && sudo systemctl restart sql-demo
```

(실제 접속 정보는 로컬의 `b6-1/AWS자료올리기.md` — git 추적 제외 — 참고)

다시 보이게 하려면 `false`를 `true`로 바꾸고 동일하게 재시작하면 됩니다.

## 2. 주제 및 데이터 소개

**주제**: 위성 궤도/주파수 — 위성이 특정 궤도 위치나 주파수 대역을 쓰겠다고 국제기구(ITU)에
신고하는 절차를 표현한 데이터베이스입니다.

**데이터 출처**: 실제 위성망 등록 DB_3075에서 17건의 실제 신고 레코드를 발췌했습니다. KOREASAT, APSTAR,
SYRACUSE, VINASAT 등 실존하는 위성망 이름과 실제 주파수 대역·궤도 파라미터를 그대로 담고
있습니다.

## 3. 테이블 구조 (ERD 요약)

```
notice (신고 원장, 부모)
  ├─ 1:N → geo    (정지궤도 위성의 궤도 위치)
  ├─ 1:N → orbit  (비정지궤도 위성의 궤도면 정보)
  └─ 1:N → freq   (신고에 포함된 주파수 대역)
```

| 테이블 | 역할 | 행 수 | PK | FK |
|---|---|---|---|---|
| `notice` | 위성망 신고 원장 (부모) | 17 | `ntc_id` | - |
| `geo` | 정지궤도(GSO) 위성의 궤도 경도 | 15 | `id` | `ntc_id → notice.ntc_id` |
| `orbit` | 비정지궤도(NGSO) 위성의 궤도면 정보 | 26 | (`ntc_id`,`orb_id`) 복합 | `ntc_id → notice.ntc_id` |
| `freq` | 신고에 포함된 주파수 대역(MHz) | 50 (쿼리 실행 후 45) | `id` | `ntc_id → notice.ntc_id` |

1:N 관계 3개(요구사항 2개 이상 충족): `notice→geo`, `notice→orbit`, `notice→freq`.

## 4. 실행 방법

### 4-1. 준비물

DB는 **SQLite**, 실행 도구는 **sqlite3 CLI** 또는 **DB Browser for SQLite**(GUI) 중 아무거나
사용하면 됩니다.

- Windows: `winget install SQLite.SQLite` (CLI) 또는 https://sqlitebrowser.org/dl/ (GUI)
- macOS: 터미널에 기본 내장되어 있거나 `brew install sqlite3`

### 4-2. CLI로 실행하기

**macOS / Linux (터미널)**

```bash
cd 제출_위성궤도주파수
sqlite3 mydb.db < schema.sql
sqlite3 mydb.db < data.sql
sqlite3 -header -column mydb.db < queries.sql
```

**Windows (PowerShell)**

> ⚠️ `Get-Content`에 반드시 `-Encoding UTF8`을 붙이세요. 빠뜨리면 `.sql` 파일의 한글 주석
> 때문에 인코딩이 깨지면서 `CREATE TABLE`의 일부 컬럼이 에러 없이 통째로 누락될 수 있습니다.

```powershell
cd 제출_위성궤도주파수
Get-Content -Encoding UTF8 schema.sql | sqlite3 mydb.db
Get-Content -Encoding UTF8 data.sql | sqlite3 mydb.db
Get-Content -Encoding UTF8 queries.sql | sqlite3 -header -column mydb.db
```

### 4-3. GUI(DB Browser for SQLite)로 실행하기

1. DB Browser for SQLite 실행 → **New Database** 클릭 → 저장 위치를
   `제출_위성궤도주파수/mydb.db`로 지정 (테이블 만들기 창은 **Cancel**로 닫기)
2. **Execute SQL** 탭 → `schema.sql` 내용 복사/붙여넣기 → 실행(▶ 또는 Ctrl+Enter)
3. 같은 방식으로 `data.sql` 실행
4. **Browse Data** 탭에서 `notice`/`geo`/`orbit`/`freq`에 데이터가 들어갔는지 확인
5. `queries.sql`의 쿼리를 하나씩 붙여넣고 실행하며 `results/` 폴더의 캡처와 비교

### 4-4. 최종 검증 (제출 전 필수)

처음부터 다시 실행해서 에러 없이 끝까지 도는지 확인합니다.

```powershell
# Windows
Remove-Item -Force final_check.db -ErrorAction SilentlyContinue
Get-Content -Encoding UTF8 schema.sql | sqlite3 final_check.db
Get-Content -Encoding UTF8 data.sql | sqlite3 final_check.db
Get-Content -Encoding UTF8 queries.sql | sqlite3 -header -column final_check.db
```

정상 실행 시 최종 행 개수: `notice` 17 / `geo` 15 / `orbit` 26 / `freq` 45
(`freq`는 `queries.sql`의 `[삭제 DELETE]` 쿼리가 초광대역 대역 5건을 정리해서 50→45가 됩니다.)

## 5. 쿼리 15개 구성

| 카테고리 | 개수 | queries.sql 내 위치 |
|---|---|---|
| 기본조회 (WHERE/ORDER BY/LIMIT) | 4 | `[기본조회 1~4]` |
| 조인 (INNER 3 + LEFT 1) | 4 | `[조인-INNER 1~3]`, `[조인-LEFT 1]` |
| 집계 (COUNT/SUM/AVG + GROUP BY) | 3 | `[집계 1~3]` |

## 6. 보너스 과제

`보너스.md`에 3개 모두 수행 기록이 있습니다.

1. 조인 vs 서브쿼리 비교 (GSO 위성망 조회를 두 방식으로 작성, 실행계획 비교)

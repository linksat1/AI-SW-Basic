## 1. 최종 결과물 4종

- [ ] `docs/architecture.png` 존재 — VPC/Subnet/Internet Gateway/EC2/Security Group과
      외부→서비스 트래픽 흐름이 표현되어 있는지 그림을 눈으로 재확인 *(파일은 이미 준비되어 있음)*
- [ ] 외부 접속 증빙 — README.md에 (A) 브라우저 접속 또는 (B) `/health` 호출 중 선택한
      방식과 접속 정보(URL/IP) 기재 + 스크린샷 1장 이상 첨부
- [ ] `docs/troubleshooting.md` — 템플릿의 `<...>` 부분을 실제 겪은 문제로 교체,
      최소 1건 이상 6단계(증상→가설→검증→조치→결과→재발방지) 모두 채움
- [ ] `docs/cleanup-checklist.md` — 실습 종료 후 실제로 삭제하며 `[x]` 체크

## 2. 과제 목표 5가지 — 말로 설명 가능한지 자가 점검

- [ ] VPC/Subnet/Route Table/Internet Gateway의 역할과 트래픽 흐름을 그림 없이 말로
      설명할 수 있다 (`평가질문_설명자료.md` 1장)
- [ ] Security Group과 IAM의 역할 차이, 최소 권한 원칙을 설명할 수 있다 (2장)
- [ ] 외부 요청이 EC2까지 도달하는 데 필요한 3가지(라우팅/퍼블릭IP/보안그룹)를 설명할 수
      있다 (3장)
- [ ] 실제로 겪은 트러블슈팅 과정을 증상→가설→검증→조치→결과→재발방지 순서로 설명할 수
      있다 (4장)
- [ ] 클라우드 과금 요인과 리소스 정리 순서·이유를 설명할 수 있다 (5장)

## 3. 네트워크 구성 요구사항 (실제 콘솔에서 확인)

- [ ] VPC 1개 생성 확인 (CIDR 10.0.0.0/16)
- [ ] Public Subnet 1개 생성 확인 (CIDR 10.0.1.0/24, 퍼블릭 IPv4 자동 할당 활성화)
- [ ] Internet Gateway가 VPC에 Attach 상태인지 확인
- [ ] Public Subnet의 Route Table에 `0.0.0.0/0 → Internet Gateway` 경로 존재 확인
- [ ] 인스턴스 내부에서 `curl https://example.com` 성공 확인 (아웃바운드 통신 증거)

## 4. 컴퓨트/웹 서버 요구사항

- [ ] EC2 인스턴스 1대가 Public Subnet에 있는지 확인
- [ ] SSH 접속이 실제로 되는지 확인 (`ssh -i <키>.pem ubuntu@<퍼블릭IP>`)
- [ ] `systemctl status nginx` (또는 사용한 웹 서버)가 `active (running)`인지 확인
- [ ] 인스턴스 내부에서 `curl -i http://localhost` → `HTTP/1.1 200` 확인

## 5. 보안 그룹 요구사항 — 반드시 콘솔에서 규칙을 직접 재확인

- [ ] 인바운드에 HTTP(80) / TCP / 소스 `0.0.0.0/0` 규칙 존재
- [ ] 인바운드에 SSH(22) / TCP / 소스가 `0.0.0.0/0`이 **아니라** 본인 IP `/32`인지 확인
- [ ] 인바운드에 포트 범위 `0-65535` + 소스 `0.0.0.0/0`인 규칙이 **없는지** 확인 (있다면 즉시 삭제)

## 6. IAM 최소 권한 요구사항

- [ ] 콘솔에 로그인한 계정이 **루트 계정이 아니라 IAM 사용자**인지 확인
- [ ] 이 IAM 사용자에 `AdministratorAccess`가 연결되어 **있지 않은지** 확인
- [ ] 연결된 정책에 S3/RDS 등 실습과 무관한 서비스 권한이 없는지 정책 JSON을 다시 읽어 확인

## 7. 외부 접속 검증 (택 1)

- [ ] (A) 로컬 브라우저에서 `http://<퍼블릭IP>` 접속 시 페이지 정상 표시 — 스크린샷 확보
- [ ] (B) 로컬 터미널에서 `curl -i http://<퍼블릭IP>/health` → `200`과 `OK` 확인 — 스크린샷 확보
- [ ] README.md에 A/B 중 어떤 방식을 선택했는지 명시했는가

## 8. 운영 안정성(과금 방지) — 실습을 완전히 마친 뒤에만 체크

- [ ] EC2 인스턴스 Terminated 확인
- [ ] EBS 볼륨(미사용 포함) 목록에 남은 것 없는지 확인
- [ ] Elastic IP를 할당했다면 Release 확인 (자동 할당 퍼블릭 IP만 썼다면 해당 없음)
- [ ] Internet Gateway Detach 및 삭제 확인
- [ ] Subnet / Route Table / Security Group 삭제 확인
- [ ] VPC 삭제 확인
- [ ] (권장) 1~2일 뒤 Billing Dashboard에서 과금 항목이 0에 수렴하는지 재확인

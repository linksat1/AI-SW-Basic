# B6-2 가이드 — AI 기반 Git 커밋 & PR 자동 생성기

이 문서는 `b6-2/` 안의 도구를 어떻게 실행하고, 왜 이렇게 설계했는지 단계별로 설명합니다.

---

## 0. 무엇을 만들었나 (요약)

`main.py commit` / `main.py pr` 두 명령으로 동작하는 Python CLI입니다.

```
main.py
ai_gitgen/
  ├── git_utils.py      git status/diff 수집 (subprocess, shell=True 없음)
  ├── safe_mode.py       민감정보 마스킹 + diff 크기 제한
  ├── prompt_builder.py  AI에게 보낼 system/user 프롬프트 구성
  ├── ai_client.py       Anthropic 공식 SDK로 실제 API 호출 + 예외 처리
  ├── validators.py      AI 응답 파싱 + 길이/형식 규칙 검증
  ├── formatter.py        터미널 출력 포맷팅
  ├── cli.py              argparse 기반 서브커맨드(commit/pr) 배선
  └── errors.py            도구 전용 예외 클래스
```

git → AI API → 검증 → 출력, 4단계로 이어지는 파이프라인입니다.

## 2. 커밋 메시지 생성 — `python main.py commit`

### 2-1. 동작 순서

1. `git status --short` 로 전체 상태를 수집합니다.
2. `git diff --staged` 로 스테이징된 변경을 우선 수집합니다.
   - 스테이징된 게 없으면 `git diff`(워킹트리 변경)로 대체합니다.
   - 그것도 없지만 `git status`에 변화가 있으면(예: 새 파일만 추가) 상태 정보만 사용합니다.
   - 아무 변경도 없으면 `커밋할 변경 사항이 없습니다` 오류를 내고 종료합니다.
3. (`--safe-mode`가 켜져 있으면) 마스킹 + 크기 제한을 적용합니다 — 3장 참고.
4. status/diff를 프롬프트로 구성해 Claude API를 호출합니다.
5. 응답을 `TITLE: .../BODY: ...` 형식으로 파싱하고, 제목 72자 규칙 등을 검증합니다.
6. 결과와 검증 통과 여부를 터미널에 출력합니다. 검증 실패 항목이 있으면 종료 코드 1을 반환합니다.

### 2-2. 실행 예시

```bash
git add .
python main.py commit
python main.py commit --model claude-opus-4-8 --max-tokens 512
python main.py commit --safe-mode
```

## 3. PR 초안 생성 — `python main.py pr`

### 3-1. 동작 순서

1. `--base`(기본값 `origin/main`)를 기준으로 `git log <base>..HEAD` 커밋 목록을 수집합니다.
2. `git diff <base>...HEAD` 로 변경 전체 diff를 수집합니다.
3. `--base`가 로컬에 존재하지 않으면(예: 원격 저장소를 아직 안 만든 경우) 자동으로 다음 순서로 대체합니다.
   - `HEAD~1` (직전 커밋과 비교)
   - 그마저 없으면(커밋이 1개뿐인 저장소) git의 "빈 트리" 해시와 비교해 저장소 시작 시점부터의
     변경 전체를 보여줍니다.
4. (`--safe-mode`가 켜져 있으면) 마스킹 + 크기 제한을 적용합니다.
5. Claude API를 호출해 제목 + `## Why / ## What / ## How to Test` 3개 섹션을 갖춘 본문을 생성합니다.
6. 제목 80자 이내, 각 섹션에 `- ` 불릿 1개 이상을 검증합니다.

### 3-2. 실행 예시

```bash
python main.py pr --base origin/main
python main.py pr --base main --safe-mode --max-diff-lines 200
```

## 4. safe-mode — 왜, 어떻게

과제 요구사항: "민감정보 마스킹" 또는 "전송 diff 크기 제한" 중 **1개 이상**을 제공해야 합니다.
이 도구는 **둘 다** `--safe-mode` 한 옵션으로 제공합니다.

### 4-1. 민감정보 마스킹 (`safe_mode.mask_secrets`)

정규식으로 아래 패턴을 탐지해 마스킹 후 전송합니다.

| 패턴 | 예시 | 마스킹 결과 |
|---|---|---|
| AWS Access Key | `AKIAABCDEFGHIJKLMNOP` | `[MASKED_AWS_ACCESS_KEY]` |
| Anthropic API Key | `sk-ant-...` | `[MASKED_ANTHROPIC_KEY]` |
| OpenAI 스타일 키 | `sk-...` | `[MASKED_API_KEY]` |
| GitHub 토큰 | `ghp_...`, `gho_...` 등 | `[MASKED_GITHUB_TOKEN]` |
| Slack 토큰 | `xoxb-...` 등 | `[MASKED_SLACK_TOKEN]` |
| `key=value` 형태 시크릿 | `password: "abc123..."` | `password=********` |
| PEM 개인키 헤더 | `-----BEGIN PRIVATE KEY-----` | `[MASKED_PRIVATE_KEY_HEADER]` |

### 4-2. 전송 diff 크기 제한 (`safe_mode.limit_diff`)

`--max-diff-lines`(기본 400줄)를 초과하는 diff는 앞부분만 잘라 전송하고, 몇 줄이 생략됐는지
안내 문구를 덧붙입니다. 큰 diff를 그대로 보내면 (1) 불필요하게 많은 토큰을 소비하고 (2) 관련
없는 파일의 민감정보까지 노출될 위험이 커지기 때문입니다.

### 4-3. 검증 방법 (직접 확인하려면)

`제출/results/03_safe_mode_masking.txt`, `04_cli_end_to_end_mocked_commit.txt`,
`05_control_without_safe_mode.txt` 를 비교해서 보면, `--safe-mode`가 켜졌을 때와 꺼졌을 때
실제로 AI에 전달되는 프롬프트 내용이 어떻게 달라지는지 직접 확인할 수 있습니다.

## 5. 검증(validation) 로직

### 5-1. 커밋 메시지

- 제목이 비어 있으면 실패
- 제목이 72자를 초과하면 실패
- 제목이 마침표로 끝나면 실패

### 5-2. PR 초안

- 제목이 80자를 초과하면 실패
- `## Why`, `## What`, `## How to Test` 3개 섹션이 모두 있어야 함
- 각 섹션에 `- `로 시작하는 불릿이 1개 이상 있어야 함

검증에 실패해도 프로그램이 죽지 않고, 생성된 결과와 함께 "⚠ 검증 실패 항목"을 출력한 뒤
종료 코드 1을 반환합니다 — CI 파이프라인에서 이 종료 코드로 실패를 감지할 수 있게 하기 위함입니다.

## 6. 모델/temperature/max-tokens 옵션

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--model` | `claude-opus-4-8` | 사용할 Claude 모델 |
| `--temperature` | (미지정) | 지정하지 않으면 요청에 아예 포함하지 않음 |
| `--max-tokens` | `1024` | 최대 출력 토큰 |

**왜 temperature 기본값이 "미지정"인가?** Claude Opus 4.7/4.8, Sonnet 5 계열은 `temperature`를
비-기본값으로 보내면 API가 400 오류로 거부합니다(샘플링 파라미터 자체가 제거됨). 그래서 사용자가
`--temperature`를 명시적으로 지정했을 때만 요청에 포함시키고, 그 모델이 거부하면 원인을 바로
알 수 있는 안내 메시지로 바꿔줍니다(`제출/results/08_temperature_not_supported_error.txt` 참고).
temperature를 쓰고 싶다면 `--model claude-sonnet-4-6` 같은 이전 세대 모델을 지정하세요.

## 8. 이 문서가 검증하지 않은 것 (한계)

이 환경에는 실제 AI API 키가 없어서, `제출/results/`의 캡처는 **네트워크 호출부(`ai_client.generate`)만
가짜 응답으로 대체한 파이프라인 배선 테스트**입니다. git 연동, safe-mode 마스킹/제한, CLI 인자
파싱, 검증 로직, 키 누락 오류 처리, 그리고 `anthropic.Anthropic` 클라이언트 생성과 `messages.create()`
호출 배선(네트워크 전송 계층만 mock)은 모두 실제로 실행해 확인했습니다. 실제 키로 실제 응답을
받는 마지막 한 단계만 사용자가 `AI_API_KEY`를 설정한 뒤 직접 실행해 확인해야 합니다.

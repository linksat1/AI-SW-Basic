# B6-2 실행 결과

이 환경에는 실제 Anthropic API 키가 없습니다(`ANTHROPIC_API_KEY`/`AI_API_KEY` 미설정,
`ant` CLI 미설치 확인 완료). 그래서 아래 10개 시나리오를 **네트워크 호출부
(`ai_gitgen.ai_client.generate`)만 가짜 응답으로 대체**하고, 그 외 모든 로직(git 연동,
safe-mode, CLI 파싱, 검증, 오류 처리, 실제 Claude 클라이언트 배선)은 실제 코드 경로로
실행해 검증했습니다. 각 파일 상단에 그 시나리오가 무엇을 mock했고 무엇을 실제로
검증했는지 명시했습니다.

| 파일 | 시나리오 | mock 여부 |
|---|---|---|
| `01_no_changes.txt` | 변경사항 없을 때 안내 메시지 + 종료코드 1 | 실제 실행 (API 호출 자체가 발생하지 않음) |
| `02_no_api_key.txt` | API 키 미설정 시 안내 메시지 + 종료코드 1 | 실제 실행 (API 호출 자체가 발생하지 않음) |
| `03_safe_mode_masking.txt` | safe_mode 모듈 단위 테스트: 시크릿 마스킹 + diff 크기 제한 | 실제 실행 (AI 호출 없음, 순수 로직) |
| `04_cli_end_to_end_mocked_commit.txt` | `commit --safe-mode` 전체 파이프라인, AI 응답만 mock | AI 응답만 mock |
| `05_control_without_safe_mode.txt` | 대조군: safe-mode 없이 실행 시 원본 시크릿이 그대로 전송됨 | AI 응답만 mock |
| `06_pr_mocked.txt` | `pr --base origin/main --safe-mode`, base ref 자동 대체 포함 | AI 응답만 mock |
| `07_validation_catches_bad_response.txt` | 72자 초과 제목 응답을 검증 로직이 잡아내는지 | AI 응답만 mock (규칙 위반 응답으로 고의 구성) |
| `08_temperature_not_supported_error.txt` | 실제 `anthropic.Anthropic` 클라이언트 + `messages.create()` 배선, 전송 계층만 400 오류로 대체 | 네트워크 전송 계층만 mock |
| `09_help_output.txt` | `--help` 출력 3종 (`main.py`, `commit`, `pr`) | 실제 실행 |
| `10_pr_validation_missing_sections.txt` | PR 필수 섹션 누락/불릿 없음을 검증 로직이 잡아내는지 | AI 응답만 mock (규칙 위반 응답으로 고의 구성) |

## 핵심 확인 사항

1. **변경사항 없음 / API 키 없음** 두 경우 모두 실제 네트워크 요청을 만들기 **전에** 조기
   차단되고, 사용자에게 구체적인 다음 행동(git status 확인, export 명령)을 안내합니다.
2. **safe-mode가 실제로 동작함**: `03`(단위), `04`(safe-mode ON, mock 호출 인자에 원본
   시크릿 없음), `05`(대조군: safe-mode OFF일 때는 원본 시크릿이 그대로 전달됨) 세 캡처를
   나란히 비교하면, 이 옵션이 장식이 아니라 실제로 프롬프트 내용을 바꾼다는 것을 확인할 수
   있습니다.
3. **base ref 자동 대체 3단계**가 실제로 동작함: `origin/main`이 없는 로컬 저장소에서
   `HEAD~1`로, 커밋이 1개뿐이면 빈 트리 해시로 자동 전환되는 것을 `git_utils` 단위 테스트와
   `06`에서 확인했습니다.
4. **검증 로직이 실제로 규칙 위반을 잡아냄**: `07`(커밋 제목 72자 초과), `10`(PR 섹션 누락/
   불릿 없음) 모두 정상적으로 "⚠ 검증 실패 항목"을 출력하고 종료 코드 1을 반환합니다.
5. **API 예외 처리 배선이 실제 코드 경로로 검증됨**: `08`은 `ai_client.generate()`를 mock한
   게 아니라, 그 안에서 실제로 생성하는 `anthropic.Anthropic` 클라이언트와 `messages.create()`
   호출 자체는 그대로 두고 네트워크 전송 함수만 API가 반환할 법한 400 오류로 대체했습니다.
   우리 코드의 예외 매칭·메시지 변환 로직이 실제로 작동함을 보여줍니다.

## 이 환경에서 확인하지 못한 것

- 실제 Claude 응답의 **문장 품질**(자연스러움, 관련성 등)은 API 키가 있어야만 확인할 수
  있습니다. `평가질문_설명자료.md` 부록에 이 한계를 명시했습니다.

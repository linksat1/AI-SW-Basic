# B6-2 평가 질문 대비 설명 자료 — AI 기반 Git 커밋 & PR 자동 생성기

과제(`과제` 파일) 3장 "과제 목표"에 명시된 5가지 항목을 순서대로 설명합니다.

---

## 1. AI API 연동 흐름(요청 구성 → 응답 처리 → 예외 대응)을 말로 설명

전체 흐름은 `ai_gitgen/ai_client.py`의 `generate()` 함수 하나에 모여 있습니다.

**① 요청 구성**
- 환경변수(`AI_API_KEY` 또는 `ANTHROPIC_API_KEY`)에서 키를 읽어 `anthropic.Anthropic(api_key=...)`
  클라이언트를 생성합니다. 키가 없으면 이 시점에서 네트워크 요청을 만들지 않고 바로
  `NoApiKeyError`를 던집니다.
- `model`, `max_tokens`, `system`(고정 지침), `messages`(git status/diff를 담은 유저 프롬프트)를
  담아 `client.messages.create(**kwargs)`를 호출합니다.
- `temperature`는 사용자가 명시적으로 지정했을 때만 kwargs에 추가합니다. (이유는 4장 참고)

**② 응답 처리**
- 응답의 `stop_reason`이 `"refusal"`이면 모델이 안전 정책상 거부한 것이므로 별도 오류로 처리합니다.
- `response.content`를 순회하며 `type == "text"`인 블록의 `.text`를 꺼냅니다(Claude 응답은 여러
  콘텐츠 블록의 리스트이기 때문에, 첫 블록이 무조건 텍스트라고 가정하지 않습니다).
- 꺼낸 텍스트를 `validators.parse_title_body()`로 `TITLE: .../BODY: ...` 형식에서 제목/본문을
  분리합니다.

**③ 예외 대응** — `anthropic` SDK가 제공하는 타입별 예외를 문자열 매칭이 아니라 각각 `except`로
구분해서 처리합니다.

| 예외 | 원인 | 사용자에게 보여주는 메시지 |
|---|---|---|
| `AuthenticationError` | 키가 잘못됨 | "API 키 인증에 실패했습니다. 키 값을 다시 확인하세요." |
| `RateLimitError` | 요청 한도 초과 | "요청 한도를 초과했습니다. 잠시 후 다시 시도하세요." |
| `BadRequestError` (메시지에 temperature 포함) | 그 모델이 temperature 미지원 | "모델 'X'은(는) temperature 옵션을 지원하지 않습니다..." |
| `BadRequestError` (그 외) | 요청 형식 오류 | "잘못된 요청입니다: ..." |
| `APIConnectionError` | 네트워크 문제 | "네트워크 연결에 실패했습니다: ..." |
| `APIStatusError` | 그 외 비-2xx 응답 | "API 오류 (status=...): ..." |

이렇게 만든 이유는, 재시도해도 소용없는 오류(키 오류, 요청 형식 오류)와 재시도하면 해결될 수
있는 오류(요청 한도, 일시적 네트워크 문제)를 사용자가 메시지만 보고 구분할 수 있게 하기
위해서입니다.

**직접 실행해 확인 가능**: `제출/results/02_no_api_key.txt`(키 누락), `08_temperature_not_supported_error.txt`
(실제 `anthropic.Anthropic` 클라이언트 생성과 `messages.create()` 호출 배선은 그대로 두고,
네트워크 전송 계층만 400 오류로 대체해 예외 처리가 실제로 동작하는지 검증).

## 2. git status/diff 수집 및 프롬프트 가공 방법

**수집** (`ai_gitgen/git_utils.py`)
- `subprocess.run(["git", *args], ...)`로 실행합니다. `shell=True`를 쓰지 않는 이유는, diff
  내용에 셸 메타문자(`;`, `` ` ``, `$()` 등)가 섞여 있어도 명령 인젝션이 발생하지 않게 하기
  위해서입니다.
- 커밋 메시지용: `git diff --staged`(스테이징 우선) → 없으면 `git diff`(워킹트리) → 그것도
  없지만 `git status --short`에 변화가 있으면 상태 정보만 사용 → 아무 변화도 없으면
  `NoChangesError`.
- PR용: `--base` 기준 `git log <base>..HEAD`(커밋 목록) + `git diff <base>...HEAD`(변경 diff).
  `--base`가 로컬에 없으면(원격을 아직 안 만든 경우 흔함) `HEAD~1`로, 그마저 없으면(커밋이
  1개뿐인 저장소) git의 "빈 트리" 고정 해시(`4b825dc6...`)와 비교해 저장소 시작 시점부터의
  전체 변경을 보여주도록 3단계로 자동 대체합니다.

**가공** (`ai_gitgen/prompt_builder.py`)
- `system` 프롬프트에는 "역할 + 출력 규칙(형식, 글자 수 제한)"만 고정으로 넣습니다. 매 요청마다
  똑같은 내용이라 프롬프트 캐싱 관점에서도 안정적인 접두사가 됩니다.
- `user` 프롬프트에는 실제 git 데이터(status/diff, 또는 커밋 로그/diff)를 그대로 이어붙입니다.
  어디서 얻은 diff인지(staged/unstaged/status-only, 또는 base ref)도 한 줄 안내로 포함해,
  모델이 맥락을 오해하지 않게 합니다.

## 3. 생성된 텍스트의 품질(길이·형식) 검증 로직

`ai_gitgen/validators.py`에 파싱과 검증이 나뉘어 있습니다.

1. **파싱**: 정규식 `^TITLE:\s*(.+)$` 로 제목을, `^BODY:\s*\n(.*)` 로 본문을 추출합니다. 혹시
   모델이 형식을 어기고 다른 형태로 응답하면, 첫 줄을 제목으로 나머지를 본문으로 쓰는
   최후 방어 로직을 둡니다.
2. **커밋 검증**(`validate_commit`): 제목이 비었는지, 72자를 넘는지, 마침표로 끝나는지 확인합니다.
3. **PR 검증**(`validate_pr`): 제목이 80자를 넘는지 확인하고, `## Why` / `## What` / `## How to Test`
   3개 섹션을 정규식으로 각각 찾아 그 섹션 본문 안에 `^\s*-\s+\S`(즉 "- "로 시작하는 실제 내용이
   있는 줄)가 1개 이상 있는지 확인합니다. 섹션 자체가 없거나, 섹션은 있는데 불릿이 없으면 각각
   다른 문구로 실패 사유를 보고합니다.
4. 검증 결과는 프로그램을 중단시키지 않고, 생성된 결과와 함께 "⚠ 검증 실패 항목"으로 출력한 뒤
   **종료 코드 1**을 반환합니다 — 결과를 사람이 직접 보고 판단할 수 있게 하면서도, 자동화
   파이프라인(예: pre-commit 훅, CI)에서는 이 종료 코드로 실패를 감지할 수 있게 하기 위함입니다.

**직접 실행해 확인 가능**: `제출/results/07_validation_catches_bad_response.txt`(72자 초과 제목을
일부러 흘려 검증이 잡아내는지), `10_pr_validation_missing_sections.txt`(섹션 누락/불릿 없음을
잡아내는지).

## 4. API 키 등 민감정보를 코드에 하드코딩하지 않고 관리하는 방법

- 코드 전체에서 API 키 문자열이 등장하는 곳은 `os.environ.get("AI_API_KEY")` /
  `os.environ.get("ANTHROPIC_API_KEY")` 단 두 줄뿐입니다(`ai_gitgen/ai_client.py`). 소스 코드
  어디에도 실제 키 값이 하드코딩되어 있지 않습니다.
- `AI_API_KEY`를 먼저 확인하는 이유는 과제 예시(`export AI_API_KEY="YOUR_KEY"`)를 그대로
  따르기 위해서이고, `ANTHROPIC_API_KEY`도 함께 인식하는 이유는 Anthropic 공식 SDK가 기본으로
  읽는 표준 환경변수명이기 때문입니다(둘 중 하나만 있으면 됩니다).
- 이 프로젝트에는 `.env` 파일이나 설정 파일에 키를 저장하는 로직이 전혀 없습니다 — 실행할 때마다
  셸 환경변수로만 전달됩니다. 만약 `.env` 파일을 쓴다면 `.gitignore`에 반드시 포함해 커밋되지
  않도록 해야 한다는 점도 README.md에 안내했습니다.
- `--temperature`가 왜 기본값 없이 "지정했을 때만 전송"인지도 같은 맥락의 안전장치입니다:
  모델이 지원하지 않는 파라미터를 무조건 보내면 매번 400 오류가 나므로, 사용자가 명시적으로
  선택했을 때만 위험을 감수하도록 설계했습니다.

## 5. 민감정보 마스킹/전송 데이터 최소화(safe-mode)가 왜 필요한가

AI API에 diff를 그대로 전송한다는 것은, **diff에 포함된 모든 문자열이 외부 서비스로 나간다**는
뜻입니다. 실수로 `.env` 파일이나 설정 파일을 스테이징한 채 커밋 메시지를 생성하면, AWS 키·API
토큰·비밀번호 같은 값이 그대로 AI 서버로 전송될 수 있습니다.

`--safe-mode`는 이를 막기 위해 두 가지를 동시에 적용합니다.

1. **마스킹**(`safe_mode.mask_secrets`): AWS 키, Anthropic/OpenAI 스타일 키, GitHub/Slack
   토큰, `key=value` 형태의 비밀번호/시크릿, PEM 개인키 헤더를 정규식으로 찾아 실제 값을
   `[MASKED_...]` 같은 플레이스홀더로 치환한 뒤 전송합니다.
2. **크기 제한**(`safe_mode.limit_diff`): `--max-diff-lines`(기본 400줄)를 넘는 diff는 앞부분만
   잘라 보냅니다. 큰 diff를 통째로 보내면 (a) 토큰 비용이 커지고 (b) 무관한 파일의 민감정보까지
   노출될 위험이 함께 커지기 때문입니다.

**"실제로 동작한다"는 것을 어떻게 증명했는가**: 마스킹이 그냥 있는 척만 하는 게 아니라는 걸
보이기 위해, 아래 3개 캡처를 나란히 준비했습니다.

- `03_safe_mode_masking.txt`: `safe_mode` 모듈만 단독으로 호출해, 가짜 AWS 키/Anthropic 키/
  비밀번호 문자열이 마스킹 결과 텍스트에 **전혀 남아있지 않음**을 `assert`로 검증.
- `04_cli_end_to_end_mocked_commit.txt`: `--safe-mode`를 켠 채 CLI를 실행하고, 실제로 AI
  클라이언트 함수에 전달되는 `user_prompt` 인자 안에 원본 AWS 키 문자열이 없는지 검증.
- `05_control_without_safe_mode.txt`: 대조군으로 `--safe-mode` 없이 실행하면, 같은 원본 AWS
  키 문자열이 `user_prompt`에 그대로 포함된다는 것을 확인 — 즉 safe-mode가 켜졌을 때와
  꺼졌을 때 실제로 결과가 달라짐을 보여, 이 옵션이 장식이 아니라 실제로 동작함을 입증합니다.

## 부록 — 이 환경에서 검증하지 못한 부분과 그 이유

이 세션에는 실제 Anthropic API 키가 없습니다(`ANTHROPIC_API_KEY`/`AI_API_KEY` 둘 다 미설정,
`ant` CLI도 설치되어 있지 않음을 확인했습니다). 그래서 아래를 명확히 구분해 안내합니다.

**실제로 실행해 검증한 것** (가짜 응답이 아닌 것)
- git status/diff 수집 로직 전체 (스테이징 우선순위, base ref 3단계 자동 대체 포함)
- safe-mode 마스킹/크기 제한 로직
- CLI 인자 파싱(`--help` 포함)
- API 키 누락 시 오류 처리(네트워크 요청 자체를 만들지 않고 즉시 안내)
- 응답 파싱 + 검증 로직(정상 응답/규칙 위반 응답 양쪽 다)
- `anthropic.Anthropic` 클라이언트 생성과 `messages.create()` 호출 배선 (네트워크 전송
  계층만 mock으로 대체해 요청 kwargs와 예외 변환 로직을 실제 코드 경로로 검증)

**사용자가 직접 실행해서만 확인 가능한 것**
- 실제 키로 실제 Claude 응답을 받아, 그 응답이 실제로 자연스러운 커밋/PR 메시지인지
  (문장 품질 자체는 API가 살아있어야만 확인 가능합니다)

이 구분은 b6-1(AWS 실습 과제)에서 제가 실제 AWS 계정 없이는 검증할 수 없었던 부분을 솔직하게
안내했던 것과 같은 원칙입니다 — 가짜 실행 결과를 진짜처럼 보이게 만들지 않습니다.
